# Архитектура Интерфейсов Стенда

Цель: не путать роли устройств и понимать, что можно централизовать через `UNO Q`, а что лучше оставить отдельным прибором.

## 1. Вывод

Полностью заменить все подключения к ПК одним `UNO Q` нельзя без потери качества проверки.

Можно:
- централизовать управление, HMI, телеметрию и команды через `UNO Q`;
- оставить `Blue Pill` заранее прошитым и управлять им только по UART;
- использовать `ST-Link` только на этапе разработки/прошивки;
- использовать `Saleae Logic` только на этапе HIL-проверок deadtime/overlap.

Нельзя нормально заменить через `UNO Q`:
- полноценный `Saleae Logic` для независимой проверки перекрытий ключей;
- надежный SWD-debug/programming `Blue Pill` без отдельной сложной подсистемы.

## 2. Режимы Работы

### 2.1. Development / HIL

Это текущий надежный режим для доводки и тестов.

| Подключение к ПК | Зачем нужно |
|---|---|
| `UNO Q USB/ADB/COM10` | HMI, команды, телеметрия, прошивка UNO Q |
| `ST-Link USB` | прошивка/восстановление `Blue Pill` по SWD |
| `Saleae USB` | независимая проверка PWM/deadtime/overlap |

Плюс низковольтная коммутация:
- `UNO Q D0/D1 <-> Blue Pill PA2/PA3` UART `115200`;
- `Blue Pill <-> STEVAL J2` PWM/EM_STOP/ADC/I/O;
- `Blue Pill <-> AS5600` I2C2 `PB10/PB11`;
- общий `GND` всей логики.

### 2.2. Bring-Up Без Приборов

Минимальный режим после того, как прошивки уже залиты и HIL прошел.

| Подключение к ПК | Зачем нужно |
|---|---|
| `UNO Q USB/ADB` | HMI, команды, статус |

Отключаем от ПК:
- `ST-Link`, если Blue Pill уже прошит;
- `Saleae`, если не делаем HIL-capture.

Что остается между платами:
- `UNO Q <-> Blue Pill UART`;
- `Blue Pill <-> STEVAL`;
- `Blue Pill <-> AS5600`.

Этот режим годится для обычной проверки статуса и аккуратного запуска, но не доказывает deadtime/overlap в момент теста.

### 2.3. Боевой Минимум

Для финального использования стенд должен работать без `ST-Link` и без `Saleae`.

Обязательные связи:
- оператор/ПК/планшет -> `UNO Q HMI`;
- `UNO Q MCU Serial1` -> `Blue Pill UART`;
- `Blue Pill TIM1 PWM/EM_STOP/ADC` -> `STEVAL`;
- `Blue Pill I2C2` -> `AS5600`;
- общий `GND` логики.

Перед таким режимом обязательно иметь свежий HIL PASS.

## 3. Текущие Интерфейсы И Порты

### 3.1. ПК <-> UNO Q

| Канал | Порт/адрес | Назначение |
|---|---|---|
| USB serial/upload | `COM10` | прошивка `UNOQ_MOTOR` через `arduino-cli` |
| ADB | device `3880458060` | доступ к Linux-части UNO Q |
| HMI forward | `127.0.0.1:18080 -> UNO Q:8080` | `/api/status`, `/api/cmd` |
| LAN bridge optional | `tools/ui_http_bridge.py` | доступ к HMI с телефона/планшета через LAN |

### 3.2. UNO Q MCU <-> Blue Pill

| UNO Q | Blue Pill | Назначение |
|---|---|---|
| `D1 / TX / Serial1 TX` | `PA3 / UART RX` | команды к Blue Pill |
| `D0 / RX / Serial1 RX` | `PA2 / UART TX` | ответы/телеметрия от Blue Pill |
| `GND` | `GND` | общая земля |

Параметры:
- baud `115200`;
- runtime frame protocol `UNOQ_MOTOR` -> `bluepill_uart_pwm_pio`;
- command stream сейчас ограничен примерно `100 Hz`.

### 3.3. ПК <-> Blue Pill Через ST-Link

| Канал | Назначение |
|---|---|
| `SWDIO` | прошивка/debug |
| `SWCLK` | прошивка/debug |
| `NRST` | reset target |
| `3.3V sense` | опорное питание ST-Link |
| `GND` | общая земля |

Это лучший способ прошивки `Blue Pill` при разработке.

### 3.4. ПК <-> Saleae Logic

| Saleae | Blue Pill / STEVAL logic |
|---|---|
| `CH0` | `PA8 PWM-1H` |
| `CH1` | `PB13 PWM-1L` |
| `CH2` | `PA9 PWM-2H` |
| `CH3` | `PB14 PWM-2L` |
| `CH4` | `PA10 PWM-3H` |
| `CH5` | `PB15 PWM-3L` |
| `CH6` | `PB12 EM_STOP` |
| `GND` | общий логический `GND` |

Automation:
- Logic2 automation port `10430`;
- устройство `CA43870A1D2AF34D`.

Saleae нужен именно как независимый прибор. Если его заменить на чтение внутри прошивки, мы перестанем проверять реальные внешние PWM-линии.

### 3.5. Blue Pill <-> AS5600

| Blue Pill | AS5600 |
|---|---|
| `PB10 I2C2_SCL` | `SCL` |
| `PB11 I2C2_SDA` | `SDA` |
| `3.3V` | `VCC` |
| `GND` | `GND` |

Проверка:
```powershell
py -3 -u .\tools\encoder_test.py --url http://127.0.0.1:18080 --duration 10 --poll 0.05
```

Критерий:
- `enc_ok_ratio=1.000`;
- `enc_raw` читается;
- при вращении магнита/вала `enc_raw` меняется.

## 4. Можно Ли Прошивать Blue Pill Через UNO Q

Теоретически да, но это отдельная доработка. Есть два варианта.

### 4.1. Вариант A: оставить ST-Link

Рекомендовано сейчас.

Плюсы:
- надежно;
- уже работает;
- есть recovery, если Blue Pill прошит криво;
- не конфликтует с runtime UART.

Минусы:
- еще один USB к ПК.

### 4.2. Вариант B: UART bootloader через UNO Q

Возможно, если добавить аппаратные линии:

| UNO Q GPIO | Blue Pill | Зачем |
|---|---|---|
| GPIO output | `BOOT0` | вход в STM32 ROM bootloader |
| GPIO output | `NRST` | reset Blue Pill |
| UART TX/RX | `PA10/PA9` bootloader UART или текущий `PA3/PA2`, если выбран совместимый UART | загрузка firmware |
| `GND` | `GND` | общая земля |

Что надо сделать в прошивке/софте:
- режим `BP_BOOTLOAD`, где `UNO Q` перестает слать runtime control frames;
- прозрачный UART bridge между Linux/HMI и Blue Pill bootloader;
- скрипт загрузки `.bin` через STM32 bootloader protocol;
- жесткий запрет `START/PWM` во время bootload;
- автоматический reset обратно в normal mode после прошивки;
- fallback на `ST-Link`, если bootloader не поднялся.

Риск:
- если bridge или BOOT0/NRST сделаны неправильно, Blue Pill можно временно потерять;
- для первого внедрения все равно нужен `ST-Link` как спасатель.

Вывод: можно сделать позже, но это не первоочередная задача для безопасного запуска инвертора.

## 5. Можно Ли Заменить Saleae Через UNO Q

Полноценно нет.

Почему:
- Saleae проверяет реальные внешние PWM-линии `PA8/PB13/...`;
- анализ deadtime/overlap требует независимого прибора;
- встроенная прошивка может только сообщить, что она "пыталась" выставить безопасные PWM, но не докажет, что на пинах нет перекрытия;
- UNO Q не является многоканальным быстрым логическим анализатором для 6 PWM + EM_STOP.

Что можно добавить вместо полной замены:
- self-test telemetry из Blue Pill: счетчики режима, fault, TIM1 state, computed deadtime config;
- простую loopback-проверку отдельных линий на низкой частоте;
- сохранение последних команд/статусов в HMI;
- "HIL required" флаг: перед HV разрешать запуск только если есть свежий Saleae PASS.

Но для настоящего HIL `Saleae` остается отдельным прибором.

## 6. Рекомендуемая Дорожная Карта

### Этап 1. Зафиксировать стабильный режим

Оставить текущую архитектуру:
- `UNO Q` = управление/HMI;
- `Blue Pill` = realtime PWM/safety;
- `ST-Link` = прошивка Blue Pill;
- `Saleae` = независимый HIL.

### Этап 2. Сделать Standalone Run Mode

Добавить в документацию и HMI явный режим:
- `DEV/HIL`: ST-Link + Saleae подключены;
- `RUN`: подключен только UNO Q, Blue Pill уже прошит, Saleae не обязателен;
- `HV`: разрешен только после свежего HIL PASS.

### Этап 3. Опционально: Blue Pill UART Bootload

Если реально надо убрать `ST-Link` из регулярной работы:
- добавить BOOT0/NRST проводами к UNO Q;
- сделать bootloader bridge;
- тестировать только при отключенном HV/J7;
- оставить ST-Link как recovery.

### Этап 4. Не Убирать Saleae Из HIL

Saleae можно отключать в боевом режиме, но не заменять в тестовом режиме. Это прибор, который ловит именно фатальные для ключей ошибки: overlap, deadtime, EM_STOP timing.

## 7. Практический Ответ На Вопрос

Да, можно сделать так, чтобы в обычной работе к ПК был подключен только `UNO Q`.

Но для разработки и доказательной проверки безопасности лучше оставить три USB-роли:
- `UNO Q` для управления;
- `ST-Link` для прошивки/спасения Blue Pill;
- `Saleae` для независимой проверки PWM.

Самый безопасный компромисс: не пытаться тянуть Saleae через UNO Q, а разделить режимы `HIL` и `RUN`.
