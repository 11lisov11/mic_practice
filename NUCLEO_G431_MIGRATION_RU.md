# MIC_AI: переход на NUCLEO-G431RB и X-NUCLEO-IHM09M2

## 1. Принятое решение

Новая целевая архитектура:

```text
телефон/ПК --Wi-Fi--> UNO Q --изолированный UART--> NUCLEO-G431RB
                                                     |
                                                     +-- X-NUCLEO-IHM09M2
                                                               |
                                                               +-- 34-pin IDC --> STEVAL-IPM15B
                                                                                  |
                                                                                  +-- J3 --> двигатель
                                                                                  +-- J4 --> 15 V
                                                                                  +-- J7 --> 125..400 VDC
```

`X-NUCLEO-IHM09M2` выбирается вместо `X-NUCLEO-IHM09M1`: M2 является актуальной заменой M1 и поддерживается ST Motor Control SDK. Blue Pill и самодельный 34-контактный переходник из рабочей силовой конфигурации исключаются.

Первый программный этап выполняется на официальном примере `ACIM V/F Open Loop` из `X-CUBE-MCSDK 6.4.2`. После проверки измерений, защит и двигателя добавляется `LSO-FOC`.

## 2. Что заказать

Обязательно:

| Позиция | Количество | Требование |
|---|---:|---|
| `NUCLEO-G431RB` | 1 | Именно RB, не G431KB |
| `X-NUCLEO-IHM09M2` | 1 | Актуальная версия; M1 не покупать |
| IDC-шлейф 34 pin | 1 | Шаг 1,27 мм, разъёмы 2x17 с ключом, прямое соединение pin 1 -> pin 1 |
| Изолятор UART | 1 | `ISO7721DWR` либо готовый двухканальный UART-изолятор 3,3 В с каналом в каждую сторону |
| Источник 15 В | 1 | `Mean Well HDR-30-15`, 15 В/2 А/30 Вт или эквивалент |
| LM2596 15 -> 9 В | 1 | Питание `VIN` Nucleo без USB |
| Отдельный SAFE БП для UNO Q | 1 | USB-C БП либо изолированные 7..24 В на `VIN`; его минус только `SAFE_GND` |
| Источник J7 | 1 | Предпочтительно 0..600 В, CV/CC, не менее 1,5 кВт для двигателя до 1 кВт |
| Внешний E-STOP/контактор | 1 | Физически снимает питание J7, не зависит от прошивки |
| Корпус, PE, закрытые клеммы | комплект | Никаких открытых точек 125..400 ВDC |

Рекомендуемый источник J7 для лабораторной работы: `ITECH IT-M3135`, `0..600 В`, `0..5 А`, `1500 Вт`. При 325 В его предел мощности соответствует примерно 4,6 А, чего достаточно для двигателя до 1 кВт с разумным запасом на исследовательском стенде.

Доступный в России вариант для пониженной мощности: `АКИП-1143А-600-5`, `0..600 В`, до `5 А`, но с общим ограничением `850 Вт`. При 325 В предел мощности соответствует примерно `2,6 А`; он подходит для наладки и работы без полной механической нагрузки, но не для полной мощности двигателя 1 кВт.

`Mean Well CSP-3000-400` (`200..400 В`, 7,5 А, 3 кВт) допускается только как последующий стационарный источник. Для первого запуска он слишком мощный, имеет высокий минимальный диапазон тока и не заменяет лабораторный CV/CC-источник, E-STOP и выходной контактор.

## 3. Домены земли

После подключения `STEVAL-IPM15B` через 34-pin разъём Nucleo относится к силовому домену:

```text
HOT_GND = NUCLEO GND = X-NUCLEO GND = STEVAL J2 GND = STEVAL J7 DC-
SAFE_GND = UNO Q GND = безопасная сторона UART-изолятора
```

`HOT_GND` и `SAFE_GND` напрямую не соединять.

`X-NUCLEO-IHM09M2` является переходником сигналов, а не гальваническим изолятором. Поэтому прямой UART `UNO Q <-> Nucleo` допустим только при физически снятом J7 и для низковольтной отладки. В итоговой сборке UART проходит через `ISO7721DWR`.

Запрещено при подключённом J7:

- подключать USB Nucleo/ST-Link к обычному ПК без подтверждённой безопасной схемы изоляции всего стенда;
- соединять UNO Q GND с Nucleo GND;
- подключать обычный Saleae или заземлённый осциллограф к Nucleo/STEVAL;
- выводить AS5600, SWD или другие HOT-провода за пределы закрытого корпуса.

## 4. Почему UART, а не SPI

Для связи UNO Q с Nucleo используется UART:

- существующий протокол проекта уже содержит CRC, sequence, timeout, команды и телеметрию;
- требуется два сигнальных канала вместо четырёх у SPI;
- достаточно одного `ISO7721`;
- скорость 115200 бод достаточна для команд 50 Гц и телеметрии;
- SPI1 Nucleo использует выводы, пересекающиеся с PWM/ADC конфигурацией motor-control shield.

Штатные `PA2/PA3` не использовать для UNO Q: MCSDK применяет их для USART2 и виртуального COM-порта ST-Link/Motor Pilot.

Отдельный канал UNO Q:

| Сигнал | Nucleo | Разъём X-NUCLEO-IHM09M2 | Назначение |
|---|---|---|---|
| `NUCLEO_TX` | `PB6 / USART1_TX` | `CN10 pin 17` | Телеметрия Nucleo -> UNO Q |
| `NUCLEO_RX` | `PB7 / USART1_RX` | `CN7 pin 21` | Команды UNO Q -> Nucleo |
| `HOT_3V3` | `3V3` | HOT-сторона изолятора | Питание VCC2 |
| `HOT_GND` | `GND` | HOT-сторона изолятора | Питание GND2 |

Соединение `ISO7721DWR`:

| Откуда | ISO7721 | Куда |
|---|---|---|
| UNO Q `D1/TX` | safe input B -> hot output B | Nucleo `PB7/RX` |
| Nucleo `PB6/TX` | hot input A -> safe output A | UNO Q `D0/RX` |
| UNO Q `3V3`, `SAFE_GND` | `VCC1`, `GND1` | Только SAFE-сторона |
| Nucleo `3V3`, `HOT_GND` | `VCC2`, `GND2` | Только HOT-сторона |

У каждой стороны изолятора поставить 100 нФ непосредственно у выводов питания. Скорость на первом этапе `115200 8N1`; heartbeat/timeout оставить `50 Гц / 300 мс`.

## 5. Сборка Nucleo и IHM09M2

1. Не подключать J4, J7, двигатель, USB и UNO Q.
2. Установить `X-NUCLEO-IHM09M2` сверху на оба ST Morpho разъёма Nucleo без смещения ряда.
3. На IHM09M2 оставить `J1` разомкнутым, как требует UM3030.
4. Подключить ключевой IDC-шлейф: IHM09M2 `J7` -> STEVAL-IPM15B `J2`, pin 1 к pin 1.
5. На STEVAL выставить для официального ACIM-примера:
   - `SW3 = 2-3` (`NTC`);
   - `SW1, SW2, SW4 = 1-2` (`amplified`);
   - `SW5, SW6 = open`;
   - `SW7, SW8 = closed` (`3-shunt`).
6. Двигатель подключить к `STEVAL J3` только после низковольтной проверки выходов.
7. `STEVAL J7`: плюс источника DC на `J7 +`, минус на `J7 -`.
8. PE соединить с металлическим корпусом, радиатором, если он доступен для прикосновения, и рамой двигателя. PE не соединять намеренно с `J7 -`.

## 6. Питание 15 В и Nucleo

HOT-сторона:

```text
230 VAC -> Mean Well HDR-30-15 -> +15V_HOT / HOT_GND
+15V_HOT -> STEVAL J4 positive
HOT_GND  -> STEVAL J4 negative
+15V_HOT -> LM2596, настроенный на 9.0 V -> Nucleo VIN
HOT_GND  -> LM2596 GND -> Nucleo GND
```

Перед подключением Nucleo выставить LM2596 ровно на `9,0 В` под нагрузкой. Не подавать 15 В непосредственно на `VIN` Nucleo: официальный диапазон для рассматриваемой конфигурации `7..12 В`.

Такое питание обеспечивает `E5V` на pin 25 motor-control connector, как требует официальный пример. Не питать Nucleo одновременно от `VIN` и USB без проверки положения силовых перемычек платы.

SAFE-сторона:

```text
отдельный изолированный БП -> UNO Q USB-C или VIN
UNO Q 3V3/SAFE_GND -> только SAFE-сторона ISO7721
```

Один источник 15 В нельзя одновременно использовать как HOT-питание STEVAL/Nucleo и как SAFE-питание UNO Q: после соединения с Nucleo его минус становится `HOT_GND`.

## 7. AS5600

AS5600 остаётся на стороне Nucleo и физически находится внутри закрытого силового корпуса:

| AS5600 | Nucleo-G431RB |
|---|---|
| `VCC` | `3V3` |
| `GND` | `HOT_GND` |
| `SCL` | `PB8 / I2C1_SCL` |
| `SDA` | `PB9 / I2C1_SDA` |

Поставить подтяжки 4,7 кОм к 3,3 В, только если их нет на модуле AS5600. Перед окончательной пайкой проверить, что в сгенерированном MCSDK-проекте `PB8/PB9` не назначены другим функциям.

## 8. Прошивка

### Уже подготовлено в репозитории

Каталог `nucleo_g431_uart_bridge_pio` содержит собираемый для `NUCLEO-G431RB` UART-каркас на `USART1 PB6/PB7`. Он совместим с текущим протоколом UNO Q, реализует CRC, sequence, счётчики ошибок и timeout 300 мс. В профиле по умолчанию силовой backend является stub: любая команда `ENABLE` отклоняется с fault, TIM1/PWM/ADC и выводы STEVAL не конфигурируются. Отдельный диагностический профиль описан ниже.

### Статус TIM1 и ADC

В проекте теперь две раздельные сборки:

- `nucleo_g431_uart_bridge` — основная безопасная заглушка. TIM1 и ADC motor backend в ELF отсутствуют, любая команда `ENABLE` отклоняется;
- `nucleo_g431_pwm_bench` — только низковольтная проверка NUCLEO и IHM09M2 логическим анализатором при физически отключённом J7. В ней настроены PLL 170 МГц, TIM1 center-aligned 10 кГц, шесть комплементарных выходов с предварительным dead-time 2 мкс и низкочастотное чтение сырых ADC-кодов.

Стендовая сборка разрешает PWM только для точной комбинации `ENABLE + DIAG_PWM + MODE_DIAG`. Все три фазы имеют 50 % duty. Любой другой режим, дополнительный флаг, сервисная команда, `E-STOP`, ошибка backend или потеря UART более 300 мс снимает `MOE`, отключает `CCER` и возвращает шесть выводов в GPIO LOW.

`PA6 / J7-1` в стендовой сборке постоянно удерживается в активном LOW-состоянии `EM_STOP`; `shutdown_released` остаётся false. Поэтому эта сборка не предназначена для управления IPM, двигателя или проверки с силовым напряжением. Полноценная конфигурация ниже должна появиться только в проекте, сгенерированном из официального примера `ACIM V/F Open Loop`:

| Функция | G431RB | IHM09M2 J7 | Требование |
|---|---|---:|---|
| Фаза U, верх | `PA8 / TIM1_CH1` | 3 | PWM advanced timer |
| Фаза U, низ | `PA7 / TIM1_CH1N` | 5 | Комплементарный PWM |
| Фаза V, верх | `PA9 / TIM1_CH2` | 7 | PWM advanced timer |
| Фаза V, низ | `PB0 / TIM1_CH2N` | 9 | Комплементарный PWM |
| Фаза W, верх | `PA10 / TIM1_CH3` | 11 | PWM advanced timer |
| Фаза W, низ | `PB1 / TIM1_CH3N` | 13 | Комплементарный PWM |
| Shutdown/diagnostic | `PA6 / TIM1_BKIN` либо generated enable GPIO | 1 | Назначение и полярность только из board profile STEVAL-IPM15B |
| Ток U | `PA0 / ADC` | 15 | Injected conversion, синхронная с TIM1 |
| Ток V | `PC1 / ADC` | 17 | Injected conversion, синхронная с TIM1 |
| Ток W | `PC0 / ADC` | 19 | Injected conversion, синхронная с TIM1 |
| Шина DC | `PA1 / ADC` | 14 | Regular conversion, UV/OV protection |
| Температура | `PC2 / ADC` | 26 | NTC protection |

Обязательный gate перед заменой `motor_backend_stub.cpp`:

1. `TIM1` работает в center-aligned режиме; `CH1/CH2/CH3` и `CH1N/CH2N/CH3N` принадлежат одному таймеру.
2. Частота PWM и deadtime взяты из MC Workbench для выбранного двигателя и board profile, а не скопированы механически из F103.
3. Idle-state всех шести PWM безопасен; после reset, fault, timeout и `STOP` отсутствуют активные импульсы.
4. Break/shutdown имеет подтверждённую для STEVAL-IPM15B полярность и аппаратно снимает `MOE` без участия основного цикла.
5. Измерение трёх токов запускается триггером TIM1 в допустимой точке PWM; Vbus и NTC не конфликтуют с injected conversions.
6. Потеря UART более 300 мс вызывает вызов motor stop и аппаратное отключение PWM.
7. До успешного Saleae-теста всех шести каналов при физически снятом J7 проект не получает статус motor-ready.

Диагностические 10 кГц и 2 мкс не являются параметрами будущего ACIM-регулятора. Финальные частота PWM, dead-time, синхронные injected ADC conversions и полярность fault/shutdown должны быть взяты из MC Workbench после ввода параметров двигателя и выбора board profile. Ручной bench backend после интеграции MCSDK в силовой сборке не используется.

Проверки каркаса:

```powershell
py -3 -m platformio run -d C:\mic_practice\nucleo_g431_uart_bridge_pio -e nucleo_g431_uart_bridge
py -3 -m platformio run -d C:\mic_practice\nucleo_g431_uart_bridge_pio -e nucleo_g431_pwm_bench
py -3 C:\mic_practice\tools\nucleo_bridge_selftest.py
py -3 C:\mic_practice\tools\platformio_env_safety_check.py
py -3 C:\mic_practice\tools\protocol_contract_check.py
py -3 C:\mic_practice\tools\full_system_preflight.py --build-only
```

Прошивать `nucleo_g431_pwm_bench` разрешается только без HV и при снятом кабеле J7 между IHM09M2 и STEVAL-IPM15B. Проверяемые каналы: `PA8/PA7`, `PA9/PB0`, `PA10/PB1`. До физического измерения всех шести сигналов, dead-time и поведения при timeout результат остаётся только compile-time подготовкой.

Текущая Blue Pill остаётся отдельной legacy-целью. Для поиска причины нагрева подозрительной платы подготовлены два минимальных environment и инструкция `BLUEPILL_THERMAL_DIAGNOSTIC_RU.md`; рабочая motor-control прошивка Blue Pill при этом не заменена и не удалена.

Официальный инструментальный набор:

- `X-CUBE-MCSDK 6.4.2`;
- `STM32CubeMX 6.12.0` или новее;
- `STM32CubeG4 FW 1.3.0` или новее;
- `STM32CubeIDE`.

Официальные GNU Tools for STM32, GDB, CMake, Ninja, STM32CubeProgrammer, ST-LINK GDB server и STM32CubeMX2 установлены через официальный STM32 VS Code Extension Pack. MCSDK остаётся не установлен: ST выдаёт ссылку только после принятия лицензии через MyST либо guest e-mail; отправка формы от имени пользователя автоматически не выполняется.

Порядок разработки:

1. В MC Workbench открыть пример `ACIM V/F Open Loop` для `NUCLEO-G431RB + X-NUCLEO-IHM09M2 + STEVAL-IPM15B`.
2. Ввести параметры шильдика двигателя: число пар полюсов, номинальное фазное напряжение, частоту, ток и максимальные обороты.
3. Сгенерировать STM32CubeIDE-проект с HAL.
4. Не менять сгенерированные TIM1 PWM, ADC, break/fault и motor-control pin mappings.
5. Добавить модуль `mic_uart_bridge` на `USART1 PB6/PB7`, сохранив текущий 32-байтный протокол UNO Q.
6. Команды `START/STOP/SET_SPEED/CLEAR_FAULT` преобразовать в публичные API MCSDK; телеметрию формировать из состояния MCSDK, Vbus, температуры, токов и fault-кода.
7. Любая потеря UART более 300 мс должна выполнять motor stop; запуск после восстановления только новой явной командой.
8. Сначала тестировать без J7: сборка, UART, timeout, fault, статические уровни и отсутствие PWM после reset.
9. Затем проверить ШИМ логическим анализатором при снятом J7.
10. Только после этого использовать регулируемый HV-источник с CC, начиная с минимального допустимого для STEVAL напряжения и малого ограничения тока.

`LSO-FOC` подключать только после подтверждённого V/F и измерения параметров двигателя. Для FOC дополнительно нужны `Rs`, `Rr`, `Lls`, `Llr`, `Lms`, ток намагничивания, инерция и трение.

## 9. Что исключается из первой ревизии

- самодельный прямой разъём Blue Pill -> STEVAL;
- SPI между UNO Q и моторным контроллером;
- SRD-12VDC-SL-C в цепи 325 ВDC;
- мост KBPC5010 и самодельный предзаряд для первого запуска;
- прямой USB/Saleae/осциллограф на HOT-сторону при J7;
- управление вентилятором до завершения основной motor-control конфигурации.

При программируемом изолированном источнике J7 с управляемым подъёмом напряжения и CC отдельный самодельный сетевой мост не нужен. Если позже будет выбран прямой выпрямитель 230 VAC, это отдельная силовая ревизия с DC-контактором, рассчитанным предзарядом, сетевой защитой и отдельным review.

## 11. Gate перед заказом и подачей питания

Перед заказом проверить точные артикулы: `NUCLEO-G431RB`, `X-NUCLEO-IHM09M2`, `IDC 34 pin 2x17`. Перед первым включением должны быть известны данные шильдика двигателя и выбран конкретный источник J7. До появления платы Nucleo и генерации MCSDK-проекта существующая Blue Pill прошивка остаётся тестовой legacy-базой и не переносится на G431 механически.
