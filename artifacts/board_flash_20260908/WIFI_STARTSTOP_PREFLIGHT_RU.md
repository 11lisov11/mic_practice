# Подготовка START/STOP и автономного Wi-Fi, 08.09.2026

## Что проверено

- UART UNO Q — Nucleo продолжает работать, счётчики ошибок 0.
- Через ADB выполнен HTTP POST на локальный HMI UNO Q:
  `/api/stop-sequence`, тело `{}`. Ответ `ok=true`,
  `STOP=True; PRECHARGE_OFF=external-autonomous-no-control; outputs_off=1`.
- После STOP: SAFE, PWM=0, возраст ответа Nucleo 17 мс,
  `mc_good=14099`, `mc_good_cnt=15632`, оба счётчика ошибок 0.
- `web_hmi_command_guard_selftest.py`: 138 программных проверок PASS.
- `web_hmi_control_access_selftest.py`: 9 программных проверок PASS.
  Эти selftest используют тестовые RPC, а не запускают подключённый привод.

## Что пока не проверено

- Команда START на подключённом оборудовании не отправлялась.
- Подтверждения текущего физического отключения IPM для нового этапа
  от пользователя ещё не получено. ШИМ и двигатель не запускались.
- Прямое управление ПК → Wi-Fi UNO Q пока не работает.
  STOP через ADB не является доказательством управления по Wi-Fi.
- Работа и восстановление сервиса после удаления USB-питания не проверены.

## Диагностика сети

- ПК: Ethernet, 192.168.1.145/24; маршрут к UNO Q идёт через Ethernet,
  подсеть 192.168.1.0/24, без промежуточного маршрутизатора на этом маршруте.
- UNO Q: wlan0 UP, 192.168.1.138/24, шлюз 192.168.1.1.
- HMI слушает 0.0.0.0:8080; localhost HTTP через ADB отвечает.
- Прямой `Invoke-RestMethod http://192.168.1.138:8080/api/status`
  возвращает запрет доступа к сокету; curl также не соединяется.
- На ПК работают AmneziaVPN и AmneziaVPN-service. Блокировка LAN
  со стороны VPN является гипотезой, не установленной причиной.
- Настройки VPN, брандмауэра и маршруты не изменялись.

## Ограничения следующего этапа

- Снять только соединения с ПК, но сохранить UART TX/RX и GND между
  UNO Q и Nucleo; обеим платам нужно независимое корректное питание.
- Обычный USB-анализатор сохраняет проводную связь с ПК. Его можно
  оставить на изолированных от силовой части платах для логического теста,
  но нельзя считать стенд физически отключённым от ПК при подключённом
  анализаторе. Перед подачей HV без измерительной изоляции его снять.
- Рабочий MCSDK сейчас сообщает MC_UNDER_VOLT (DC-шина 0 В).
  Не обходить защиту и не подменять измерения ради запуска без IPM.
- Для наблюдения активного ШИМ без силовой части использовать отдельный
  явно обозначенный диагностический тест, не выдавая его за пуск двигателя.

Итог: STOP через USB/ADB подтверждён; START и автономное Wi-Fi-управление
ещё не подтверждены. USB пока следует оставить для диагностики.
