## Найдено И Исправлено

Первый прогон прерван ReadTimeout анализатора на длинной записи 24 МГц. Рабочая прошивка восстановлена; неудачная запись не засчитана. Для последующего прогона использованы короткая запись 24 МГц и длинные записи 4 МГц.

Второй прогон обнаружил после SET FREQ 0 тайм-аут контроллера и аварийную реакцию HMI. Точный механизм задержки UART не установлен. Wi-Fi-команда 0 Гц теперь использует подтверждаемую процедуру STOP с немедленным снятием ARM вместо простого изменения задания. Регрессионный HTTP-тест подтверждает отправку STOP, подтверждение выключенных выходов и снятие ARM. После установки исправления третий физический прогон прошёл все четыре проверки.

Установленный HMI `server.py`: SHA256 `b915f07648692e13e06a4ca50a235c385310cbb4439d1cd14accc41ec17f4c79`. Исходная калибровка сохранена без новых измерений. Предыдущий архив `startup_update_2026100706.zip` содержит более ранний HMI без этого исправления; не использовать его Linux-файл для отката текущего сервера.

## Восстановлено

После теста Nucleo прошита исходным рабочим HEX `2026100705`; проверка записи и отдельное чтение BIN совпали. Итоговая пара: Uno Q `2026100706`, Nucleo `2026100705`, HMI-профиль HV, SAFE, PWM=0, Vbus=0, калибровка действительна.

Функции включения/выключения PWM, обработчики TIM1 и процедура защиты сравнивались по машинному коду объектов и совпали между рабочей прошивкой и копией. Инициализация таймера также совпала. Стендовая копия отличается разрешением работы при измеренной нулевой шине и виртуальным напряжением только для нормирования модуляции; при реальной шине выше 2 В копия блокирует выходы. Производственный исходный код не изменён этой генерацией.

Активный ШИМ неизменённого производственного образа с рабочим напряжением шины, силовой IPM, вращение и токи двигателя этим тестом не приняты. Новый физический тест внешнего BKIN не выполнялся. Стендовая прошивка не оставлена на плате.
