# Исправление HMI LOCAL STOP — 2026-10-12

Исправление установлено на Uno Q Linux. Прошивки остаются Uno Q `2026101205`
и Nucleo `2026101204`; перепрошивка и команды CLEAR, ARM, START не выполнялись.

Причина ошибки: `AppState.arm_snapshot(status)` вычислял LOCAL STOP из своего
выходного словаря ARM, который не содержит `bp_status`. Поле всегда получалось
нулевым; попытка добавить причину в этом же месте не выполнялась.

Теперь поле вычисляется из телеметрии контроллера. Общий форматтер добавляет
`current=LOCAL_STOP_PC13`, сохраняя `first=MCSDK_FAULT` и все поля первого
fault-снимка. Интерфейс показывает «ЛОКАЛЬНЫЙ STOP B1 (PC13)», а подробности
первого события доступны в подсказке. Ключи событий и диагностики учитывают
текущий fault и защёлку: смена STOP фиксируется даже при неизменном первом
снимке. Периодические строки STAT также содержат состояние защёлки.

Исправлены основной `web_hmi/server.py`, `web_hmi/static/app.js` и генератор
`tools/prepare_trial_wait_fix.py`. Общее преобразование находится в
`tools/prepare_local_stop_hmi_fix.py`. Старые артефакты оставлены неизменными.

## Проверки

- `hmi_stop_selftest_r1/report.json`: 70 проверок, настоящий HTTP GET
  `/api/status` с фиктивным RPC без команд; старая ошибка воспроизведена как
  отрицательный контроль. Проверены API, псевдонимы mc/bp, форматтер,
  сохранность первого снимка, запись и дедупликация STOP, JavaScript-подпись
  и воспроизводимость результата основным генератором.
- `hmi_stop_guards_r1/report.json`: пять существующих наборов проверок команд,
  пробного пуска, авторизации и калибровки прошли.
- `hmi_stop_install_r2/scope_verify.json`: AST функций управления и HTTP
  обработчиков совпадает с установленным исходным HMI. Изменены только пути
  производного статуса, отображения и журналирования. Выдаваемый по Wi-Fi
  JavaScript побайтно совпадает с проверенным кандидатом.
- `hmi_stop_installed_idle_r1/summary.json`: 30 секунд прямого Wi-Fi, 29
  полученных снимков, UART `22369 -> 22959` (+590), ошибок HTTP и новых ошибок
  UART нет. SAFE, PWM=0, ARM=0, шина по телеметрии 0 В.
- `hmi_stop_installed_idle_r1/local_stop_verify.json`: во всех снимках сырой
  `bp_status=mc_status=141`, производный `hmi_local_stop_latched=1`, текущий
  fault=ESTOP. Причина LOCAL STOP присутствует в API, MC_FAULT_CONTEXT,
  MC_FAULT_DIAG и STAT. Все ранее скачанные строки журнала сохранены.
- Первый снимок не изменён: reason=8, UART flags=0, current/occurred masks
  `0x0004/0x0004`, motor state=10, sequence=227, TX status=0.

## Следующий шаг и границы доказательств

Пользователь подтвердил нажатие и затем отпускание B1 USER. После подтверждения
отпускания выполнена отдельная 10-секундная пассивная запись прямого Wi-Fi:
`b1_released_idle_r1/summary.json` и `release_verify.json`. Во всех 11 снимках
LOCAL STOP=1, `bp_status=0x8D`, SAFE, PWM=0, ARM=0, шина по телеметрии 0 В.
UART +200 корректных сообщений, новых ошибок нет. Первый fault-снимок сохранён.
Удержание защёлки после подтверждённого отпускания проверено. CLEAR, ARM и
START не отправлялись.

Флаг LOCAL STOP подтверждён на установленной паре при выключенном ШИМ.
Останов активного ШИМ, время отключения, запрет повторного ENABLE и безопасный
сброс на физическом стенде этим прогоном не проверены. Разрешение силового
пуска не создано; прежнее одобрение другой пары не переносится.
