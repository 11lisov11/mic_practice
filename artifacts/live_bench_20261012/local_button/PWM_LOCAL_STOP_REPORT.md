# Измерительная проверка B1 при работающем ШИМ — 2026-10-12

Проверка останова прошла на изолированной тестовой копии рабочих исходников.
Силовой вход STEVAL J1 и двигатель U/V/W физически отключены, J4 выключен;
пользователь подтвердил измеренную шину 0 В. Во время прогона телеметрия
также показывала 0 В. Силовой двигатель не запускался.

затем предоставил `C:/Users/USER/Desktop/Session 8.sal`. Копия сохранена в
`pwm_session_r2/manual_run_1791818470131763700/operator_capture.sal`.

## Происхождение тестовой копии и границы проверки

Тестовая пара — Uno `2026101298`, Nucleo `2026101299`, полученная из рабочих
`2026101205/2026101204`. Копия оставляет реальную ADC-телеметрию и использует
контроль шины <=2 В, потолок команды 5 Гц и аппаратно исполняемый в MCU
предел ШИМ 3 с. Виртуальные 310 В используются только для нормировки модуляции
в изолированной оснастке; такой образ не предназначен для силовой работы.

`pwm_fixture_code_r1/report.json`: десять сравниваемых машинных секций ШИМ,
IRQ и функций STOP совпадают с рабочей сборкой; адреса релокаций не входят в
это сравнение. Инициализация TIM1 и исходники защёлки также совпадают.
`pwm_fixture_selftest_r5/report.json`: 1038 STOP-проверок, граничные тесты шины,
1000 значений raw ADC, 451 значение фильтрованного напряжения, устаревший ADC,
лимит 3 с и переполнение счётчика, декодер диагностики и девять отрицательных
вариантов HMI прошли. Оба целевых образа собраны; проверка загрузчика Uno прошла.

По желанию пользователя использованы только шесть подключённых ШИМ. Фронт
PC13 не записан, поэтому точная задержка от B1 до выключения не измерена.
Эта проверка не является активным прогоном исходного производственного BIN,
проверкой силовых ключей под напряжением, испытанием внутренних защит IPM или
принудительной подачей ENABLE после защёлки STOP. Силовой допуск не создан.

## Сохранённые неуспешные этапы

Первый прогон остановился по лимиту, пользователь не услышал сигнал/не успел
нажать B1. Его отчёт оставлен с `pass=false`; как кнопочный STOP он не засчитан.
После сброса Nucleo был зарегистрирован UART-сбой FE/NE. Снимок и шесть
последующих наблюдений сохранены в `reset_boundary_observation.json`: счётчик
ошибок стабилен при +82 правильных кадрах, выходы выключены, шина 0 В.
Обычный CLEAR на изолированной оснастке принят; до/после сохранены в
`before_boundary_clear.json` и `after_boundary_clear.json`. Физический источник
этого сбоя не определён; событие не скрыто и не представлено как успешный тест.

Автоматический повторный захват не смог открыть вторую сессию при уже идущей
пользовательской записи Saleae; до START эта попытка не дошла. Успешный прогон
выполнен с пользовательским захватом, без переключения его записи.

## Восстановление

**Дополнение 2026-10-12:** пользователь холодно перезапустил Uno Q; RPC
восстановилась без новой прошивки. За 30 секунд по Wi-Fi получено 591 новое
корректное сообщение, ошибок нет; версии 1205/1204, SAFE, PWM=0, ARM=0,
шина по телеметрии 0 В. HMI и калибровка по хешам сохранены. Подробности:
`post_cold_boot_r1/REPORT.md`. Описанная ниже незавершённая RPC-проверка
является историческим этапом, а не текущей проблемой.

Оба рабочих образа записаны и проверены: Nucleo побайтовым readback, Uno
проверкой загрузчика и скетча. Установленный HMI сохраняет SHA256
`21bda96fae14b0fa13db27d1fb21edd6f059e6d2037199944bdae50999569276`, калибровка
`a89603c26f3dfa6287c304134121028db6ebdb9adeda4b58d99040530ffeea17` не менялась.
Тестовый HMI на 8081 остановлен. Новый ноль калибровки не записывался.

После восстановления RPC не вернулась. Перезапуск HMI и verify-only
перезапуск Uno с согласованным сбросом Nucleo (без записи flash) не помогли.
Пока восстановление не считается полностью завершённым: пользователь
получил просьбу холодно перезапустить Linux Uno переподключением его USB.
После этого требуются живая идентичность 1205/1204, пассивная проверка связи,
выходов и сохранности калибровки. Логи всех попыток сохранены в `pwm_session_r2`.
