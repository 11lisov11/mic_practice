# Установка BKIN-диагностики

Дата: 2026-10-15, 13:26 МСК. Установлена пара Uno Q `2026101507` / Nucleo
`2026101506` из соседней сборки `manual_scalar_bkin_trace_r3`.

## Запись и проверка

- ПК определил Uno Q `3880458060` на COM10 и Nucleo G431RB через ST-Link
  `003A002C3335510933383531`.
- Перед записью свежая телеметрия показала `SAFE`, PWM=0, ARM=0, Vbus=2 В,
  валидный возраст измерения 13 мс.
- Nucleo записана через ST-Link; двоичное чтение диапазона `0x08000000–`
  совпало с образом побайтно, SHA-256:
  `EF41FB5DCF3AD65B32631D3DD5FA34A87FDE259C927233CD17DBAC589A5B76B5`.
- Uno Q записана через Arduino CLI; проверка загрузчика и образа прошла.
- HMI файлы заменены на диагностическую версию и сервер перезапущен. На устройстве
  сохранён прежний ключ управления; файл ключа и само значение в этот журнал не
  копировались.
- Точки Vbus по API не изменились: ноль `0/0 В`, верхняя точка `322.7/325 В`,
  статус двухточечной проверки `passed`.

## Проверка после установки

10 секунд опрашивался только GET `/api/status`: 50 ответов из 50, все состояния
`SAFE`, PWM=0, Vbus менялся от 1 до 2 В, новых HTTP-ошибок не было. Ошибки UART
(`mc_uart_error_flags`, `mc_last_uart_error_flags`) равны 0. За это время
счётчики bad-пакетов не выросли. Диагностика сохраняет `mc_bad_cnt=1`,
`bp_bad_cnt=1` и транспортный код `7=LINK_TIMEOUT`; MCSDK сообщает
`MC_UNDER_VOLT` при обесточенной шине. Причина и момент защёлкнутого timeout
не устанавливались; новых ошибок во время наблюдения нет.

HMI отдаёт страницу с кнопкой «Считать снимок BKIN». Авторизованный запрос
`GET /api/bkin-trace` прошёл с HTTP 200 и вернул `available=false`,
`reason=not_received`: после установки не возникало нового BKIN-события.
Предыдущий D1-снимок регистров сохранён до прошивки в
`previous_d1_break_snapshot.json`; это не высокочастотная осциллограмма PA6.

Силовой пуск после установки не выполнялся. Эта пара собрана и установлена, но
не получила электрическую квалификацию: остаются неподтверждёнными внешний
soft-start HIL и аппаратное BKIN-срабатывание. Для следующего настоящего снимка
нужен новый BKIN после завершения безопасной квалификации и теста; Saleae не
подключается.

Точные журналы команд: `nucleo_flash.log`, `nucleo_readback.log`,
`uno_flash.log`, `uno_verify.log`, `hmi_deploy.log`.
