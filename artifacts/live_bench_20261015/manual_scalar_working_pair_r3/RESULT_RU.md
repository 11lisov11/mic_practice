# Ручной V/f: базовый прогон пройден, расширение остановлено защитой

Постоянная пара Uno2026101505 / Nucleo2026101504 остаётся установленной.
Калибровка сохранена. Два реальных силовых прогона дали разные результаты.

| Проверка | Результат |
|---|---|
| 5→10→5 Гц, разгон2, снижение0.5 Гц/с | Пройдена; все три задания достигнуты |
| Ручная сессия дольше прежних30с ARM | Подтверждена в базовом прогоне |
| Ровное вращение, ускорение и снижение | Подтверждено пользователем для5→10→5 |
| 5→20→50→20→5 Гц | Не пройдена: Break при разгоне к20 |
| Достижение20 и50 Гц | Не достигнуты, не квалифицированы |
| Причина останова расширенного прогона | TIM1 Break / MC_DP_FAULT0x0400; физическая причина неизвестна |
| Связь после останова при включённом силовом | 10.969с/+221 свежий ответ без критических ошибок |
| Активная осциллограмма шести выходов новой пары | Не снята |
| Измеренная скорость вала и фазные токи | Не квалифицированы |

В базовом прогоне51 активный отсчёт и34.531с между первым и последним таким
отсчётом;36.359с от запроса START до конца наблюдения. Это не точное время
вращения. DC-шина315..319 В, UART fault/bad/CRC/sequence0, MCSDK masks0/0.
Один START, один предварительный CLEAR архивированной стартовой DP-записи,
штатный STOP. Пользователь: «Да, вращался ровно, ускорение и снижение заметны».
Доказательства: `powered_manual_1792055829149795500/report.json`, `samples.json`.

В расширенном прогоне один START и ни одного CLEAR. После установления5 Гц
задано20; последний активный отсчёт частоты поля12.6 Гц, контекст аварии12.7 Гц.
UART fault/bad/CRC/sequence оставались0, отброшенных Uno байтов0.
STOP подтверждён: SAFE/ШИМ0/ARM0/estop1, авария сохранена, повторного пуска нет.
Доказательства: `powered_manual_1792056019094763800/report.json`, `samples.json`.

Снимок первой рабочей защиты: BIF1/B2IF0/BKE1/MOE0, PA6 HIGH при входе в IRQ.
Сохранённый контекст старше IRQ на43мс: seq116, state6, шина317 В, температура52°C.
Это не мгновенное измерение у фронта SD. По одному уровню PA6 нельзя установить
длительность импульса или отличить перегрузку, провал15 В, помеху и другие
источники Break. Токи фаз/напряжениеJ4/формаSD в этом прогоне не измерены.

Статический разбор обнаружил скачок задания амплитуды на10 Гц:20→35.921 В
пиковых, поскольку ниже порога используется20 В, выше —2π·f·0.5717009.
Это аналитический расчёт по установленному коду, не модель двигателя и не
измеренная осциллограмма. Связь с Break не доказана: базовый10 Гц успешен,
авария возникла позже. ЗаконV/f, фильтры и защиты по гипотезе не менялись.

Силовое и15 В после аварии оставлены включёнными по просьбе пользователя.
Стенд закрыт, обе платы на повербанке, двигатель подключён, USB ПК и ВСЕ
щупы/GND Saleae сняты. Пассивное наблюдение11 отсчётов/10.969с: шина318 В,
выходы выключены, авария сохранена,+221 ответ без критических ошибок UART.
Это наблюдение под питанием, а не проверка выключения силового.
Для чтения записей отключать питание не требуется. Следующий диагностический
шаг зависит от доступности изолированной записи SD; обычный Saleae к
включённой неизолированной силовой части не подключаем.

Сводка `hardware_review/hardware_verification.json`, график реальной редкой
телеметрии `hardware_review/actual_runs.png`. График показывает частоту поля
из MCSDK и DC-шину, не скорость ротора и не форму импульсов ШИМ.

## История установки и программной проверки, до этих силовых прогонов

Комплект Uno2026101505 / Nucleo2026101504 установлен и проверен. Полное чтение
памяти Nucleo совпало с образом, Uno проверена загрузчиком. Итог SAFE/PWM0/ARM0.
Восемь отсчётов покоя:7.703с/+154 корректных ответов, UART/bad/CRC/sequence0,
авария0, поле0/valid1, шина10 В. Калибровка не менялась. Полный ручной
прогон5→10→5 на момент этого установочного снимка ещё не выполнялся.
Его последующий успех и отдельный отказ расширенного прогона описаны выше.

Ползунок на реальной Uno проверен для0,5,20,50,20,5,0 Гц. Настройки разгона2 и
замедления0.5 приняты. Это подтверждение команд, а не осциллограмма активного ШИМ.
Saleae на обесточенной силовой части записал12.06272с низких шести входов.
Результаты находятся в ../manual_scalar_working_pair_r2/physical_idle_slider.

Первую силовую проверку остановил чрезмерный критерий хостового теста для
Zephyr UART_ERROR_NOISE bit5. Он исправлен без смены прошивки; другие флаги,
потери байтов, CRC, последовательность и таймауты остаются ошибками.
Вторая проверка показала реальный дефект источника частоты: MCSDK API читал
fRotorFreqRef_RPM, который обновляется только в VF_CL. В VF_OL частоту нужно
получать от ramp manager через ACIM_VF_GetMecSpeedRefUnit. Это исправлено.
Продолжение сегмента теперь ждёт MC_HasRampCompletedMotor1: целочисленное
округление частоты может дать равенство с целью до окончания сегмента.

Обе целевые сборки готовы, Nucleo0 ошибок/0 предупреждений. qualification.json
сверяет исходники и образы. Реальный код MCSDK ramp/VF_OL/API выполнен на хосте:
140073 утверждения, воспроизведение старого нулевого отсчёта, регрессия раннего
округления. HAL и мотор здесь не моделируются как физический стенд.
Другие проверки: UART2106 и четыре обнаруженные мутации; Nucleo2103,
Uno9308, HTTP33, текстовый RouterBridge20, обычный HTTP42, пять наборов защит.
Статические UI-файлы сохранены из уже проверенного комплекта.

Набор предназначен для постоянной работы: режимы/частота/темпы меняются онлайн.
Найденное исправление кода записано; повторять прошивку для изменения частоты
или темпа не требуется. Точки калибровки сохранены.
Основные АЦП, фильтры, генератор ШИМ и аппаратные защиты не изменены.

Перед записью пользователь подтвердил OFF/мультиметр<20 В/USB обеих плат.
Связь Uno после холодного старта восстановлена проверкой существующего образа
и сбросом MCU без его перезаписи. После установки архивирован один таймаут
программирования; один STOP/CLEAR при выключенной силовой части снял его.
Установка: installation/report.json и сохранённые статусы/логи рядом.

Исторический следующий шаг после установки выполнен: пользователь подтвердил
переход на повербанк/снятые USB ПК и щупы/GND Saleae/закрытый стенд/питание ON;
прогон5→10→5 пройден, затем STOP. Активная осциллограмма ШИМ всё ещё не снята.
Текущий следующий шаг указан в начале отчёта: определить источник рабочего Break.
