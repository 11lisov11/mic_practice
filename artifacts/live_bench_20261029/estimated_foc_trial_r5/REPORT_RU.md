# Расчётный FOC загружен; проверка без силового завершена

Установлена и проверена пара **Uno Q 2026102951 / Nucleo 2026102952**.
Итоговый образ Nucleo — из `estimated_foc_trial_r5`, его SHA256:
`240c22c0d722ac47aec257dacf2ea3ae0a5f69b7c0fee008ae7f964ec2ccfc42`.
Образ Uno:
`724f0e9d9270627004b505a450b1899953b0bd0e7aa23a33ff6929e717f34151`.
Оба образа сверены чтением обратно; Uno записывалась один раз. После
исправлений Nucleo Uno повторно не прошивалась. Веб-сервер обновлён под
новый формат статусов. Калибровка DC-шины до/после записи неизменна.

Профиль постоянно присутствует в Nucleo после загрузки, но сам не запускает
выходы. CRC32C **1354279011**, источник `calculated_experimental`, значение
типа128. Измерительная квалификация7 не подделывалась. Параметры — прежний
расчётный профиль AIR56B2, Rs12,23 Ом, Rr≈11,0044 Ом, Lm≈0,494478 Гн,
Lls=Llr≈0,0336163 Гн; начальный поток0,25Вб, задание вектора тока≤0,8А.

Подготовлен первый опыт: **плавно0→5Гц за1с, всего5секунд, без нагрузки**.
Для расчётного профиля экспериментальный START допускается только в FOC,
в ограниченном режиме с таймером5с и заданием≤5Гц. Ручной бессрочный пуск,
адаптивный ШИМ и более высокое задание этим экспериментальным разрешением
не открываются. По окончании5с Nucleo выключает ШИМ из быстрого обработчика
по DWT-времени, независимо от веба; Uno сохраняет собственный резервный
таймер. Повторный запуск не возникает от старой продолжающейся ENABLE-команды.

Без силового реально измерено на STM32G431 при170МГц:

| Проверка | Максимум |
|---|---:|
| Чистое ядро FOC, 64сценария по8вызовов | **3598тактов ≈21,16мкс** |
| Наблюдатель в основном цикле, 64сценария | **23703такта ≈139,43мкс** |

Для OFF-проверки используется программный запрос того же NVIC-вектора
TIM1, потому что MCSDK маскирует UPDATE при выключенном MOE. Запрос не
включает силовые выходы и не меняет DIER/BDTR/BKE/BIE. Синтетические входы
замкнуты в отдельном состоянии проверки и не выдаются за физические токи.
Ядро должно укладываться в4000тактов, оставляя запас на адаптер. Исходное
ограничение полного быстрого пути5312тактов сохранено и действует при работе.
Это аппаратное измерение тестовых случаев, не доказательство WCET всего
обработчика для всех возможных состояний.

В процессе найдены и исправлены конкретные программные причины:

- В унаследованном make-графе оставались абсолютные пути предыдущего
  native-пакета. Теперь пути переназначаются, ELF проверяется по всем48
  единицам компиляции, наличию FOC-символов и точным52байтам профиля.
  Первоначально записанный ошибочный бинарник сообщал2940; он заменён.
- CPU-проверка ожидала прерывания таймера, которое MCSDK маскировала при MOE0.
  Теперь она явно запрашивает тот же NVIC-вектор только для OFF-проверки.
- Начальное ядро занимало5221такт, почти весь исходный бюджет. Встроены
  эквивалентные NaN-совместимые min/max; ориентация вычисляется напрямую
  нормированием двух компонент потока, без atan2→sin/cos. Сырая токовая
  проверка `hypotf(ia,ib)>trip_current` не изменена. Полоса и порог не увеличены.
- Статус FOC теперь отправляется сразу после главного ответа каждые100мс,
  чтобы фоновые страницы захватов не задерживали подтверждение режима.

Проверки на ПК: настоящий native-адаптер, профилирование, блокировки
экспериментального режима, CRC, автостоп на границе5с и при переполнении
счётчика, NaN/Inf в min/max и7200положений вектора потока. На независимой
модели с записанным шумом результат сохранился:54/60 сценариев точности,
центральный профиль4/4. Шесть сценариев с большим расхождением Rs/Lm на5Гц
не выдержали точность скорости; они не объявлены успешными. Скорость остаётся
оценкой по модели, независимого датчика вращения нет.

После записи выполнена остановленная настройка через штатный интерфейс:
MODE VF (режим транспорта), BOUNDED, разгон5Гц/с, замедление1Гц/с,
таймер5с, задание5Гц и выбор native FOC. Получено подтверждение
`algorithm_selected=algorithm_requested=2`, CRC профиля совпал. По16
последовательным статусам счётчик правильных E4-пакетов увеличивается,
счётчик плохих пакетов не растёт; общая связь свежая. Автоноль готов,
SD HIGH, конфигурация BKIN корректна. Силовой FOC ещё **не запускался**.

При выключенном J1 активен и сохранён MC_UNDER_VOLT (маска4); CLEAR не
отправлялся. Последний статус — SAFE, PWM0. По последнему подтверждению
пользователя J1/J4 выключены, платы наUSBПК; в завершившейся проверке
контроллер показывает низкую остаточную шину. Это не новое показание мультиметра.

Все636 прежних файлов захватов сохранены. Перед каждой записью Nucleo
сохранён её полный32КБ RAM, включая прежние SD/ADC/ID-данные. Диагностические
неудачи и промежуточные результаты не удалены, находятся в r1–r4. Всего в
этом этапе было5записей Nucleo: одна из-за ошибки графа сборки, затем исправления
OFF-вызова и времени расчёта. **START/CLEAR/ARM —0** во всём этапе.

Основные доказательства: `hardware_install_r1/report.json`,
`idle_verification_r1/report.json`, `verification/elf_identity.json`,
`verification/selftest.json`, `model_verification_final/report.json`.

Перед силовым опытом потребуется обычный перевод на повербанки с отсоединением
ПК/Saleae и повторная проверка автономной загрузки. Сейчас силовое включать
не запрашивалось. После перезапуска выбор режима/таймер задаются заново;
расчётный профиль и автоматическая OFF-проверка остаются в прошивке.
