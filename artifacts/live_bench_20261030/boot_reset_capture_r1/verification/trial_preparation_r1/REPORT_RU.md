# Подготовлен один новый FOC-пуск 3013/3014

Пользователь явно запросил FOC 5 Гц на 5 секунд с записью причины сброса, токов и автостопом. В этом этапе пуск, CLEAR, ARM, RESET и перепрошивка не выполнялись.

Подготовлен `tools/run_foc_boot_capture_trial.py`: существующий испытанный runner параметризован парой 3013/3014, без изменения его проверок, keepalive, команды локального 5-секундного ограничения или обработчика STOP. Его штатные снимки сохраняют токовую телеметрию и CPU/IRQ; после останова принимается сырой 1024-байтовый захват АЦП. Полный непрерывный фазный ток/RMS этим не обещается: возраст и валидность токовых пакетов остаются в записи.

Дополнительный этап читает только сохранённые файлы: проверяет CRC UART и ранней записи reset до/после, неизменность Linux boot ID и записи Nucleo, рост native tick, версию и CRC сырого АЦП. Если запись неполна либо загрузка изменилась, прогон не объявляется успешным; повторного пуска этот этап не отправляет. Все статусы и отдельный boot_evidence_audit.json сохраняются с SHA-256.

355 проверок на сохранённых данных прошли; 223 файла установленного пакета сверены по SHA. Прошивка и общий runner не менялись. Контроль текущего АЦП/наблюдателя на MCU, 1,35 А, 2048, 2 мс, 5312 тактов, физический SD и останов при потере связи сохранены. Ранее достигнутые только ~1,94 секунды до MA_CURRENT не считаются подтверждением пяти секунд.

Через async запрошено только перевести обе платы на повербанки, убрать USB ПК/Saleae, оставить 15 В, J1 выключенным, не нажимать START/RESET. Ответ ещё не получен. После ответа: сначала свежая автономная связь/zero/SD/boot/profile и свободный захват. Выбор FOC2 только в SAFE/PWM0 штатной командой, без пуска. Затем отдельное подтверждение включения J1 через soft-start, свежая проверка защит и один уже запрошенный прогон. CLEAR пользователь в этом запросе не разрешал; автоматически не отправлять.

Новая папка прогона должна быть `powered_FOC_boot_capture_20261030_r1` внутри пакета и создаваться только при готовности, без перезаписи истории. Пара 3013/3014 новая, испытаний в этой загрузке ещё не было; не подсовывать предыдущий ADC 3012 как новый и не переносить разрешение обхода архивного MA_CURRENT в активную маску защиты.
