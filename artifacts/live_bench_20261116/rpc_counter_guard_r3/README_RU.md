# Исправление проверки RPC: только ПК, без пуска

Актуальный tools/run_telemetry_deadline_trial.py принимает исторические
response/send timeout counters после отдельной тихой OFF-проверки (>=2с,
>=3ответов, продвижение кадров, свежий CRC-проверенный boot). Один guard
сохраняется через все стадии предстоящего теста. Любое изменение counter,
включая reset/wrap, защёлкивает отказ. До START продолжение запрещено,
после START существующий обработчик выполняет STOP без повторного пуска.
Baseline и причина отказа сохраняются, аппаратные counters не обнуляются.

Boot bulk OFF-only; его возраст во время RUN не является RPC-ошибкой.
После первоначальной свежей привязки CRC/identity остаются проверяемыми,
а mc_age<300мс и продвижение кадров контролируются по живой телеметрии.
Стандартная свежесть boot при OFF-проверке и остальные guards не менялись.

11 тестов пройдены. Replay20 сохранённых ответов принимает постоянный12.
Имитация пятисекундного runner завершается с историческим12; отдельные
инъекции нового response/send timeout вызывают STOP, инъекция до START
не отправляет START. Проверены reset/wrap/malformed/stale/boot изменения,
SD/BIE/температура/UART/профиль/автоноль и прежние CPU пределы.
Имитационные motor-команды в stdout тестов не отправлялись на стенд:
HTTP opener и heartbeat заменены, socket.connect запрещён.

3532 прежних файла и162 исходника установленного release проверены по SHA.
report.json и tests.log относятся только к тестам на ПК. Прошивка не нужна.
Реальных сетевых обращений/START/CLEAR/ARM/RESET/flash нет. Старый failed
autonomous report сохранён без изменений. Защиты4000/2мс/1,35А/2048 прежние.
