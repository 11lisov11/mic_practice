# Восстановление RPC без сброса плат, 2026-11-18

J1 OFF подтверждён пользователем, 15 В и повербанки оставлены включёнными.
Однократный перезапуск только принадлежащего arduino процесса HMI не помог.
Один close/open внутреннего Linux UART /dev/ttyHS1 восстановил RPC временно:
16 статусов /17,64 с без новых ошибок, затем повтор HTTP503. Короткую проверку
нельзя выдавать за окончательное устранение причины. Её исходные данные сохранены.

Для отделения Linux-клиентов выполнена одна остановленная GET-only проверка
через новый пользовательский экземпляр того же arduino-router v0.5.3: 60 GET
за60с, без MCU reset, halt, flash, START, CLEAR или прокси. Основной router
отпускал UART на время теста; восстановление его порта выполнено в finally и
подтверждено ответом true. Логи и пассивные снимки приведены в
fresh_router_isolation_r1/evidence. Диагностический роутер завершён.
Он также отличается verbose-режимом и отсутствием клиентов monitor; этот
опыт сам по себе не доказывает причину в monitor, Go-процессе или UART.

После возврата порта основной RPC прошёл отдельную проверку 90,86с /77
свежих статусов под опросом HMI. response_timeouts=209 и send_timeouts=0
НЕ росли во всём этом окне. Старые 209 ошибок не обнулены. Наблюдался тот же
Linux/native boot, без перезапуска плат. UART текущих ошибок0, автоноль3/3,
OFF64/64: быстрый расчёт3827/4000, наблюдатель25013/85000 тактов. Финальная
шина10В по телеметрии, SAFE/PWM0/HV ARM0/run_id0. Старый первый SD17,5594мс
сохранён побайтно, SD сейчасHIGH; BIEfalse и маски MCSDK0x4/0x404 остаются.
Приёмник NIS пуст, нового моторного теста не было.

Это подтверждение текущей работоспособности RPC в указанном окне, а не
доказательство постоянного устранения первичного сбоя. MCU/HMI исходники,
релизы и5921 старый файл сверены по SHA256 без изменений. Новых образов
нет. START/CLEAR/ARM/MCU reset/halt/flash0. Пределы4000тактов/2мс/1,35А/
2048 и остальные защиты неизменны. Запрошенный один CLEAR и один FOC5Гц/
5000мс ещё не израсходованы, снова разрешение не запрашивать.

Далее: пользователь включает только J1 через soft-start при закрытом стенде,
15В и повербанки оставляет, USB ПК/Saleae отключены, Пуск/RESET не нажимает.
После свежей проверки шины/RPC/SD выполнить уже разрешённый один CLEAR и
пуск только при полном восстановлении всех защит. При отказе — никаких
повторных CLEAR/пусков. Следующая новая папка FOC_5Hz_r2; прежнюю failed
FOC_5Hz_r1_RPC_preflight не перезаписывать. Сравнение NIS — только после
реальной новой записи, с учётом изменения метрики R в1715/1716.
