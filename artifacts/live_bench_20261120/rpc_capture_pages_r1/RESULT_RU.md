# Разгрузка RPC после прогона

Собрана Uno 2026112013 с веб-сервером под эту версию. Nucleo остаётся 2026111810.
До установки пара 2013/1810 прошла проверку на ПК.

Обычный GET на сохранённом прогоне сокращается с 14 330 до 8 508 байт.
Записи АЦП и наблюдателя читаются отдельными страницами по 192 байта.
При включённом ШИМ прошивка отклоняет запросы страниц. Сборка файла проверяет
номер страницы, версию Nucleo, длину и CRC32C.

Реальные записи предыдущего прогона восстановились побайтно. Проверены отказ
при повреждении, смене записи, нарушении порядка и попытке чтения без ключа.
Исходные 21 файл прогона по-прежнему совпадают с сохранёнными SHA-256.

Для новой версии собирать записи после остановки через tools/download_rpc_capture_pages.py.
Старые скрипты прогона, ожидающие эти массивы в /api/status, требуют перехода на
этот маршрут перед следующим силовым тестом. Достоверность оценки скорости и
причина пропуска GET этим изменением не проверялись.


## Проверка на стенде 21 ноября 2026

Uno 2026112013 записана один раз, полное чтение Flash совпало с образом.
Flash Nucleo 2026111810 повторно совпала с эталоном. Исходная калибровка
сохранена. Перед записью снята RAM обеих плат, 21 файл прогона сверён по SHA.

45 запросов статуса за 51,94 с, максимум 656 мс. Счётчики тайм-аутов RPC
по нулям. Nucleo во время перезапуска Uno зарегистрировала ошибку UART:
счётчик mc_bad_cnt вырос с 0 до 91 до начала проверки, затем оставался 91.
Транспортная защёлка 4 остаётся. SAFE, PWM0, автоноль готов, SD HIGH.
Команд CLEAR, START и ARM не отправляли.

Встроенный журнал Uno подтвердил отправку обычных ответов около 8,3 КБ.
Новый маршрут с ключом дошёл до Uno и вернул ожидаемое ERR NOT_COMPLETE
для обеих пустых записей. Неверная страница отклоняется с 400, запрос без
ключа с 401. Полная выгрузка с реальными данными проверена на ПК по старому
прогону; на установленной паре она ещё не проверялась.
