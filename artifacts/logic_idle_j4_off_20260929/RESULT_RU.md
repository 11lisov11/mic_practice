# Низковольтная проверка после отключения J4

Состояние со слов оператора: питание J4 и силовая часть выключены, шлейф
`IHM09M2 -> STEVAL J2` оставлен подключённым. Активные команды, прошивки и
силовое питание в этом сеансе не включались.

- Через локальный HTTP-адрес UNO Q `192.168.1.138:8080` из WSL получен свежий
  статус Nucleo: `SAFE`, `PWM=0`, `mc_fault=5`, возраст ответа менее 50 мс.
  Windows-хост с активным AmneziaVPN не открывал LAN, поэтому использован
  WSL NAT; ADB служил только для чтения токена и исходного статуса.
- Телеметрия Vbus после отключения J4 спадала от 10 до 1 В. Это показание
  Nucleo, **не** независимое измерение мультиметром на STEVAL J1.
- `STOP` отправлен по HTTP через WSL на Wi-Fi-адрес UNO Q, получен HTTP 200
  (`ok=true`, 0,167 с); после команды сохранились `SAFE`, `PWM=0`, свежий UART.
  `START`, `ARM`, `CLEAR` не посылались.
- [Исходный захват Saleae](report.json): CH0–CH5 LOW, по 0 фронтов.
  [Первый захват после STOP](../logic_idle_after_wifi_stop_20260929/) завершился
  ошибкой `ReadTimeout` и не считается доказательством. [Повторный захват](../logic_idle_after_wifi_stop_retry_20260929/report.json)
  прошёл: CH0–CH5 LOW, по 0 фронтов, пересечений нет.
- Временные диагностические прошивки UNO Q и Nucleo собраны, рабочий пакет
  проверен (`30` артефактов, `hardware_validated=false`). 17 автотестов
  сценария Wi-Fi/PWM прошли. Прошивки в платы в этом сеансе **не записывались**.

На момент этого пассивного отчёта активный прогон ещё не был выполнен.
Позднее он успешно завершён: [полный результат](../wifi_nucleo_pwm_bench_20260929_live_r3/RESULT_RU.md).
Тестовый сценарий сообщает HMI
синтетический ноль шины, поэтому запускать его можно только после
подтверждения, что силовой вход STEVAL J1 физически отсоединён, двигатель
отключён, J4 выключен и независимый мультиметр показывает менее 2 В на J1.
Шлейф J2 при этих условиях можно оставить подключённым. Программный
предохранитель проверяет до прошивки свежую производственную телеметрию
`SAFE`, `PWM=0`, `HV disarmed`, `Vbus <= 2 В`.
