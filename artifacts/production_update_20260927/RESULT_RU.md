# Рабочая прошивка и проверка перед силовыми испытаниями

Дата: 27.09.2026. Силовое питание не включалось.

## Выполнено

- Arduino UNO Q обновлена до рабочей сборки **2026092701**, не диагностической.
- Применена обработка ответа на UART-команду, замененную принудительным STOP.
  Такой ответ не обновляет телеметрию и не подтверждает CLEAR; проверки
  целостности, срока ожидания и повторного приема сохранены.
- Запись и чтение флеш-памяти проверены: `flash_unoq.log`, сообщение
  `UNO Q loader and sketch verification PASSED`.
- Рабочая прошивка Nucleo **2026091401** не менялась.
- Исправлен штатный прошивальщик: переданный AdbDevice используется как
  серийный номер UNO Q и при записи, и при последующей проверке.
- Основной пакет и ZIP обновлены: `firmware/ready_to_flash`.
  Проверка целостности 30 файлов пройдена.

## Измерено на рабочей связке

Команды STOP/CLEAR и отрицательная проверка START выполнялись через HTTP по
Wi-Fi `192.168.1.138:8080`. ARM и команды включения диагностического ШИМ
не подавались. После одного явного CLEAR выполнено 120 опросов за 97,312 с:

- `bp_bad=0`, `bp_bad_cnt=0` во всех отсчетах;
- максимальный возраст UART-телеметрии 50 мс;
- принятые UNO Q ответы: 1170 -> 2846;
- счетчик правильных команд Nucleo: 7917 -> 9593;
- SAFE, VF, PWM=0, ARM снят во всех отсчетах;
- при нулевой шине сохраняется штатный отказ undervoltage `mc_fault=5`;
- START отклонен с HTTP 409;
- Saleae подтвердил отсутствие переключений и LOW на всех шести выходах.

Это проверка конкретного интервала и выключенного состояния, не доказательство
отсутствия любых ошибок в будущем. CLEAR штатно сбрасывает счетчики; начальные
ошибки после перезапуска не скрыты, они сохранены в `idle_validation/report.json`.

## Что пока НЕ подтверждено

1. **Аппаратное SD/BKIN.** Точное подключение CH6 к PA6/TP23 и питание J4
   пользователь пока не подтвердил. Ответ «вроде да» недостаточен для
   активного воздействия на линию. Проверка не выполнялась и не отмечена PASS.
2. **Vbus.** HMI сообщает `zero-point capture is required`. Без независимого
   показания мультиметра нулевая точка не создавалась. Рабочая точка также
   не подтверждена. Число 0 в телеметрии не заменяет измерение мультиметром.
3. **Токовые каналы.** Ненулевые ia/ib/ic в HMI пока являются локальными
   измерениями UNO Q, а не подтвержденными фазными токами Nucleo/инвертора.
   Их нельзя использовать как доказательство калибровки или работы защиты.
4. В release-gate остаются открытыми `external_softstart_hil_validated`,
   `motor_profile_is_real_acim`, `generated_motor_configuration_matches_profile`
   и `ipm_sd_bkin_hardware_trip_validated`.

Предыдущий активный диагностический тест ШИМ сохранен отдельно в
`artifacts/wifi_transitions_20260927_r7`. Его привязка к прежним образам не
переписана под новый пакет. Поэтому новый пакет содержит подтвержденную
проверку статических выходов, но не присваивает старому активному тесту новый хеш.
