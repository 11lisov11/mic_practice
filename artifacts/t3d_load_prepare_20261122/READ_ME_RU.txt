Нагрузочный стенд АИР56 + HLTNC-T3D-400W-3M-BRAKE
Подготовка на ПК, 22.11.2026. Реальный T3D ещё не получен и не проверен.

ЗАПУСК
Двойной щелчок START_T3D_LOAD_CONSOLE.cmd в корне проекта.
Откроется локальная панель http://127.0.0.1:8094/ .
Для работы нужна Python 3 и pyserial 3.5 (requirements-load-bench.txt).
Первый запуск копирует config.template.json в config.local.json.
Можно сразу выбирать сценарии и нажимать «Проверить в симуляции».
Симуляция проверяет протокол и логику, не является моделью реального двигателя.
Кнопка реальной нагрузки остаётся недоступной до первичной наладки.
Путь конфигурации показан под «Что осталось проверить».

АРХИТЕКТУРА
Основное управление АИР остаётся на штатных Uno Q / Nucleo / STEVAL-IPM15B.
Программа нагрузки общается с T3D по изолированному USB-RS485 / Modbus RTU.
Меняется только оперативное задание внутреннего момента P-145; запись в EEPROM,
JOG, аппаратный ноль, снятие аварий и внутреннее включение SON не реализованы.
Нагрузочная программа не отправляет START/ARM/CLEAR/RESET асинхроннику.
При окончании/отказе: снять watchdog, записать и перечитать нулевой момент,
запросить штатную остановку АИР. Неподтверждённая остановка остаётся ошибкой.
Штатный веб-сервер АИР не изменялся и новая программа на Uno Q не устанавливалась.
Красная BSMCE04U-PP с DrufelCNC остаётся для позиционной наладки отдельно;
во время нагрузочного опыта её STEP/DIR/AVI к T3D не подключаем.

НЕЗАВИСИМОЕ СНЯТИЕ НАГРУЗКИ
Подготовлена отдельная прошивка свободной Blue Pill STM32F103C8:
load_bench/watchdog_firmware . Она не предназначена для Nucleo/Uno Q стенда.
Вывод PB12 разрешает нагрузку через гальванически изолированный выход
3.3 В -> открытый коллектор 24 В -> DI2 T3D. Внешний pulldown PB12 10 кОм.
P-101=-8: обрыв цепи DI2 включает CZERO и обнуляет команду момента.
Каждый heartbeat отвечает на свежий одноразовый запрос с CRC; он отправляется
только после свежих измерений и подтверждённого задания P-145.
TTL 750 мс. Аппаратный IWDG примерно 500 мс при зависании watchdog-МК;
реальное максимальное время отключения, в том числе сброс/потеря USB, измеряется.
Blue Pill не прошивалась. Один лишь успешный build не подтверждает работу GPIO.
STOP подтверждается ответом OFF с CRC после установки PB12=LOW; отсутствие ответа
или неполная запись не помечаются успешным снятием разрешения. Это подтверждение
МК не заменяет первичную физическую проверку входа CZERO реального T3D.

ПОДКЛЮЧЕНИЕ
Нужен изолированный USB-RS485; наличие такого адаптера в комплекте не подтверждено.
RS485 по CN1 DB44: 40=A, 41=B, 42=485 GND (проверить реальную ревизию).
Использовать разъёмную клеммную колодку DB44 с проверенной нумерацией контактов.
Сигнальная земля подключается к изолированной стороне адаптера; не соединять
её с USB/PC GND. Точные требования заземления - EN V2.3, стр. PDF 25.
CN3/CN4 имеют разные исполнения в документах: RJ45, DB9, клеммник.
Переходить к ним без проверки маркировки/распиновки фактического драйвера нельзя.
Защитное PE, сеть, штатные силовой и энкодерный кабели - по руководству именно
поставляемого драйвера. CN2 является портом родного энкодера, не портом STM32.
Разъёмы и силовую проводку менять при снятом питании и разряженных шинах.
Для части АИР сохраняется прежняя схема питания/изоляции: Wi-Fi к ПК;
не подсоединять USB/Saleae к HOT_GND работающей силовой части.

CN1: 31=COM+ (12-24 В); DI1=16, DI2=1, DI3=17, DI4=2.
DI1 - внешний SON с включением на неподвижном валу при нулевой команде.
DI2 - разрешение watchdog, через изолированный нормально разомкнутый транзистор.
DI3 - нормально замкнутая внешняя цепь разрешения, P-102=-8.
Две функции CZERO работают как OR: обрыв любой цепи обнуляет момент.
DI3 не заменяет отдельный аппаратный STOP асинхронника.
DI4 не используется. Не подавать 24 В на GPIO Blue Pill/Nucleo.
DO1=20 (SRDY), DO2=5 (ALM, ON = нет аварии), DO4=6 (BRK), DO COM=23.
DO - сигнальные выходы до 50 мА; катушку стояночного тормоза напрямую не питать.
Нужны отдельные 24 В и релейный/транзисторный каскад с подавлением выброса.
Тормоз Brake удерживает остановленный вал. Он не создаёт исследуемую нагрузку.
Таймеры BRK при вращении, сбросе и аварии обязательно проверяются с обоими роторами:
снятие SON из Python не применяется, чтобы не зажать вращающийся вал тормозом.

РЕЖИМЫ И ПАРАМЕТРЫ
parameters.csv содержит таблицу для НИЗКОСКОРОСТНОГО СОЕДИНЁННОГО стенда.
Кратко: P004=2, P026=1, P098=0, P100=1, P101=-8, P102=-8, P103=0;
P065=25, P066=-25, P075=500, P077=0, P078=400; P145..148=0;
P108=2, P109=3, P110=0, P111=8; P120..124=0;
P181=1, P182=2 (19200), P183=1 (8E1).
P-000/P-001/P-099 и параметры согласования мотора не копировать из примеров:
сохранить правильный заводской профиль комплектного мотора.
Изменения режима/связи сохраняются штатной операцией панели и проверяются
после перезапуска. Сервер не сохраняет в EEPROM промежуточные команды нагрузки.
Адрес P-145 = 145 десятичное = 0x0091, а не 0x0145.

ПЕРВАЯ НАЛАДКА ПОСЛЕ ДОСТАВКИ
1. Сверить шильдики, реальный CN1, номинальный момент, кабели и тормозной узел.
2. На разъединённых валах проверить проводку, SON, CZERO и полярности DI/DO.
   Для этой фазы отдельные пониженные ограничения: P065=5/P066=-5,
   P075=50/P078=30, P145=0. Основной runner с этими значениями откажется в запуске.
   Никакой нагрузки/момента не подавать до проверки снятия тормоза и режима.
3. Проверить знак и малую команду с ограничением скорости, вернуть P145=0.
   Измерить снятие разрешения при остановке ПК/обрыве USB/перезапуске watchdog.
4. Проверить оба независимых пути остановки, стояночный тормоз и тормозной узел.
5. На обесточенном стенде состыковать валы подобранной муфтой, выставить соосность
   и ограждение. Точные диаметры валов и модель муфты пока не известны.
6. Вернуть низкоскоростную таблицу parameters.csv, сохранить на панели,
   перезапустить и проверить командой probe. Перечитать все ключевые параметры.
7. Записать фактические USB VID/PID/serial/location в config.local.json, значения
   измерений и результаты qualification. Не переносить флаги из симуляции.
8. T3D включается внешним SON на неподвижном валу, P145=0; дождаться BRK release
   и не менее 50 мс после SON. Затем штатный запуск АИР с его защитами/автостопом.
   Supervisor можно запустить заранее: он до 30 с ждёт начала PWM, сохраняя CZERO.
9. Сначала нулевая нагрузка, затем одна малая ступень. Проверить знак мощности
   и сохранение всех журналов. Повышение режима - отдельная квалификация.

ЧИСЛЕННЫЕ ГРАНИЦЫ ПЕРВОЙ СТАДИИ
Не более 5 Гц поля АИР, 80-350 об/мин, 0.12 Н*м, 5 Вт задания,
15 Дж на опыт, 4 с от первого наблюдённого активного PWM; цикл команд 0.5 с.
Первые и последние 1 с сценария имеют нулевое задание.
1.27 Н*м - ожидаемое значение 400-Вт мотора, до сверки шильдика не квалифицировано.
Момент округляется к нулю по целым процентам P145: 1% = 0.0127 Н*м при 1.27 Н*м.
Максимум 0.12 Н*м становится командой 9% = 0.1143 Н*м.
Расчётный ограничительный запас на выпадение связи: внутренний предел 25%,
граница аварии 120% от 500 об/мин => около 19.95 Вт; за 1.2 с ещё 23.94 Дж.
Для допуска требуются подтверждённые возможности тормозного узла >=19.95 Вт
и >=38.94 Дж с учётом 15 Дж опыта. Это расчётное требование, не паспорт резистора.
Наличие резистора/надписи Brake/мощности мотора 400 Вт не подтверждает эти значения.
P/D/C: внутренний резистор - штатная перемычка P-D; внешний - только P-C
после удаления P-D, если это подтверждено для реальной ревизии драйвера.
Не соединять резистор поперёк P-N и не объединять DC-шины T3D и STEVAL.
Полные 250 Вт на валу АИР, 2720 об/мин и около 0.878 Н*м не разрешены этой стадией.
Для них отдельно проверяются длительное рассеивание, ток/нагрев АИР и диапазон FOC.
Пределы штатного стенда 1.35 А, NIS25 и временные бюджеты не изменялись.
Текущая запись CURRENT_BENCH_STATUS_RU.md не подтверждает готовность АИР к нагрузке;
в частности, полная физическая квалификация FOC остаётся незавершённой.

ЭКСПЕРИМЕНТЫ И ДАННЫЕ
zero/step/ramp/sine/prbs воспроизводимы; PRBS seed сохраняется в manifest.json.
Псевдослучайное задание двухуровневое (25/100% амплитуды, удержание 0.5 с);
из-за ограничения нарастания и целых процентов фактическая команда отличается.
experiment_plan.csv - план 45 опытов: 5 форм x 3 алгоритма x 3 независимых повтора.
Он не является очередью автозапуска. Алгоритм задаётся штатным стендом;
expected_algorithm сверяется с фактическим algorithm_selected, режим не меняется.
Для скаляра require_observer_valid=false выбирается только в его отдельной
квалифицированной конфигурации; для FOC/адаптивного режима validity обязателен.
Сравнивать одинаковые нагрузки/частоты/ограничения; порядок повторов фиксировать
до эксперимента. Делить обучение/контроль по физическим прогонам, не по строкам.
Сохраняются сырые ответы Modbus, полный статус АИР, интервалы чтения на ПК,
идентификаторы прошивок/нативного прогона, seed, команды и причины остановки.
Момент T3D - оценка электромагнитного момента, не эталон механического момента.
RPM T3D получены с энкодера через медленный опрос, не синхронный эталон MCU.
Эти данные годятся для начальных медленных опытов; для быстрого сравнения
наблюдателей нужна отдельная квалифицированная запись ABZ с аппаратными метками.
ABZ: OA+/OA-=13/28, OB+/OB-=14/29, OZ+/OZ-=15/30, GND=12 по EN V2.3.
Фактическое наличие ABZ у заказанной ревизии ещё не подтверждено.
Нужны дифференциальный приёмник, согласование/изоляция и 3.3-В уровни к STM32;
прямое подключение дифференциальных/5-В линий к произвольному GPIO не подготовлено.
ABZ-путь в прошивки АИР этой задачей не внедрялся.
Симуляционные записи явно помечены simulation=true/hardware_validated=false.

КОМАНДЫ ИЗ КОРНЯ
python -X utf8 -m load_bench check
python -X utf8 -m load_bench ports
python -X utf8 -m load_bench parameters
python -X utf8 -m load_bench simulate --profile step --out artifacts/t3d_demo_new
python -X utf8 -m load_bench probe --config load_bench/config.local.json
python -X utf8 -m load_bench run --config load_bench/config.local.json --profile step --out artifacts/t3d_real_new
probe только читает параметры/телеметрию. run сначала проверяет квалификацию,
параметры и USB-идентичность; чужие порты автоматически не подбирает.
В режиме run используются только функции 03/04/06, запись только P145.
Симуляционный fixture_only конфиг запрещён для реального запуска.
Неподтверждённый путь остановки никогда не помечается completed=true.

ИСТОЧНИКИ И РАСХОЖДЕНИЯ
Переданные пользователем EN V2.3 и RU PDF лежат в docs/vendor/HLTNC_T3D.
Официальная страница источников: https://www.hlt-cnc.com/download
Карта Modbus: filename V3_1_14, титульный лист V3.3; локальная копия названа по титулу.
В примере на стр. PDF 7 CRC для 01 03 00 05 00 02 указан как 94 37;
стандартный Modbus CRC даёт D4 0A. Реализация проверена известными CRC-векторами,
а не подогнана под ошибочный пример. В EN V2.3 также расходятся названия/распиновки
CN3 в разных документах и верхняя граница P182 с перечнем поддерживаемых скоростей.
Поэтому выбраны 19200 8E1 и CN1 с обязательной сверкой фактической ревизии.
