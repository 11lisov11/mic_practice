# Проверка автономного Wi-Fi-маршрута, 29.09.2026

## Условия

Пользователь подтвердил отключённые `STEVAL J7` и двигатель, измеренную разряженную DC-шину и подключение Saleae. После теста уточнил, что питание `STEVAL J4` не подключено. По ответу HMI до и после теста: `vdc=0.0 V`, `state=SAFE`, `pwm=0`, `bp_fault=5`, `hmi_hv_armed=0`. Компьютер использовал ADB только для чтения уже существующего ключа авторизации; команды и телеметрия передавались по прямому Wi-Fi HTTP на `192.168.1.138:8080`.

## Результаты

- `MODE VF`, `SET FREQ 5`, `SET FREQ 20`, `SET FREQ 0` приняты по Wi-Fi. Телеметрия показала соответственно `freq_cmd=0, 5, 20, 0 Hz`; всё время оставались `SAFE`, `pwm=0`, шина 0 В.
- `POST /api/start-sequence` вернул HTTP 409 и сообщение об активном `mc_fault=5`. Это ожидаемое блокирование пуска, не испытание рабочего запуска.
- `POST /api/stop-sequence` вернул HTTP 200. Окончательное состояние: `SAFE`, `pwm=0`, `freq_cmd=0`.
- Журнал HMI зафиксировал команды, отклонённый START и STOP. Полный машинный протокол: [report.json](report.json).
- Пассивная запись Saleae после STOP: CH0–CH5 без фронтов и в низком уровне; CH6 (`PA6`) без фронтов и в высоком уровне. Исходные данные: [digital.csv](saleae_after_stop/csv/digital.csv).
- После команд 30-секундный пассивный опрос по Wi-Fi: 38 выборок, `bp_good` 40766 -> 41294, `bp_bad` 2 -> 2, `bp_bad_cnt` 1 -> 1, без ошибок HTTP. [summary.json](post_30s/summary.json).
- Офлайн-проверки: 4 теста безопасного сценария и 157 тестов охраны команд HMI прошли.

## Что пока не доказано

Уставка частоты не равна физическому разгону: при `mc_fault=5` ШИМ не включался, а J4 не питал IPM. Код `5` в протоколе Nucleo означает `UNO_FAULT_INTERNAL`: он может представлять разные внутренние причины, а не однозначный код пониженного напряжения. Не проверены рабочие импульсы и dead-time текущих производственных прошивок, аварийное отключение `SD/BKIN`, двигатель и силовая часть. Накопленные ошибки UART не равны нулю (`bp_bad=2`, `bp_bad_cnt=1`); причина отдельного нарушения последовательности пока не доказана. Локальное расширение HMI для раздельных счётчиков ошибок UART ещё не развёрнуто на UNO Q, потому что gate развёртывания требует исправного состояния контроллера. Переход к питанию J7 по этому протоколу не разрешён.

При испытаниях с силовой частью все проводные связи компьютера, ST-Link и Saleae должны быть физически сняты. Система остаётся в SAFE до отдельной проверки питания J4, канала Vbus, аппаратного SD/BKIN, UART и локальной аварийной остановки.
