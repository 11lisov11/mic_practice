# Проверка управления ШИМ по Wi-Fi, 27.09.2026

## Результат

На физическом стенде прошли 29 сценарных проверок и три проверки переходов
START -> ШИМ -> STOP в непрерывных записях Saleae. Итоговый report.json: pass=true.

Управляющие команды отправлялись HTTP-запросами на 192.168.1.138:8080.
Этот адрес проверен на интерфейсе wlan0 UNO Q. ADB/ST-Link использовались для
загрузки/проверки прошивок и чтения диагностической информации, не для START/STOP.
Маршрут управления: Wi-Fi -> Linux UNO Q -> MCU UNO Q -> UART -> Nucleo.

## Измерения

- Шесть выходов: PA8/PA7, PA9/PB0, PA10/PB1.
- Короткий точный захват: 24 Мвыб/с, несущая приблизительно 10,025 кГц,
  минимальный dead time около 2,0 мкс во всех трех парах.
- Одновременный HIGH комплементарных выходов не обнаружен.
- Три непрерывных захвата по 4,055 с при 2 Мвыб/с:
  обычный STOP, ESTOP, повторный запуск после CLEAR и нового ARM.
- После последнего импульса во всех трех непрерывных записях наблюдалось
  более 2,2 с LOW без повторного включения. Это измерение в пределах записи,
  не утверждение о бесконечной длительности и не точная задержка Wi-Fi -> STOP.
- Трехсекундный лимит: останов с фиксацией ESTOP, как предусмотрено прошивкой.
  Обнаружение по HTTP через 3,844 с от отправки START; запрос START занял 0,484 с.
  Независимый поток отправил 11 heartbeat без ошибок, исключая намеренную
  потерю heartbeat в этом сценарии. Это не аппаратное измерение точности таймера.
- Потеря heartbeat: отключение обнаружено через 3,171 с при watchdog 3 с;
  независимый резервный лимит был 8 с.
- Проверены запреты запуска без ключа, без ARM, с неверной фразой ARM,
  после STOP без повторного ARM и при зафиксированном ESTOP.

## Исправления и ограничения

Добавлено распознавание одного ответа на принудительно замененную UART-команду:
он отбрасывается без обновления телеметрии и без подтверждения CLEAR.
Проверки целостности, срока ожидания и запрет повторного приема сохранены.
Изменение проверено в диагностической сборке; обычная сборка тоже компилируется.
Оно пока НЕ включено в восстановленный пакет firmware/ready_to_flash.

Исправлен отсчет времени в тесте лимита: от START, а не от окончания экспорта
Saleae. Учтено штатное защелкивание ESTOP при истечении лимита.

В итоговом прогоне зарегистрирован один USB ReadTimeout с сохранением ошибки
и повтором захвата. В отдельных новых захватах выключенного состояния еще
встречаются начальные импульсы; независимые подтверждения LOW сохранены.
Их первопричина не установлена. В трех непрерывных записях повторных импульсов
после останова нет. Предыдущие неуспешные прогоны r1-r6 не удалены.

Это диагностический фиксированный ШИМ без силовой части, не трехфазный V/f
и не испытание двигателя. Телеметрия шины диагностической Nucleo синтетическая.
PA6/SD и аппаратный BKIN не проверены. Допуск к силовому запуску не выдан.

## Состояние после проверки

Обе прежние рабочие прошивки восстановлены с проверкой записи.
SAFE, VF, PWM=0, ARM снят, все шесть выходов LOW.
При нулевой шине mc_fault=5 ожидаем. После перезагрузок счетчики bp_bad и
bp_bad_cnt равны 1: восстановленное рабочее состояние не объявляется
готовым к ARM/силовому запуску. Полный green-результат относится к указанным
диагностическим сценариям, а не ко всем режимам рабочей прошивки.

## Файлы

- report.json: команды, результаты, хеши образов, измерения и восстановление.
- transition_1/capture.sal: обычный START/STOP.
- transition_2/capture.sal: START/ESTOP.
- transition_3/capture.sal: повторный запуск и STOP.
- active_after_wifi_command/capture.sal: точный захват при 24 Мвыб/с.
- production_restored/capture.sal: выходы после возврата рабочих прошивок.
- logs/: сборка, запись и проверка прошивок.

Программные проверки: 13 тестов стендового измерителя, тесты C++ очереди
замененных ответов, 155 проверок HMI, проверки UART/MCSDK-контрактов прошли.
