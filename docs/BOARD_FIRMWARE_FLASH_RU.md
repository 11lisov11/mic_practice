# Комплект прошивок MIC_AI

Этот комплект предназначен для `NUCLEO-G431RB` (`STM32G431RBT6`), переходной платы `X-NUCLEO-IHM09M2`, силового модуля `STEVAL-IPM15B` и `Arduino UNO Q`. Это именно UNO Q: бинарник не подходит для классической Arduino Uno AVR.

## Что прошивается

- `nucleo/ACIM-NUCLEOG431RB-IPM15B-VF_OL.hex` - MCSDK 6.4.2, разомкнутое скалярное V/f для IEK AIR56B2: 1 пара полюсов, 50 Гц, 2720 об/мин, двигатель соединён треугольником на 220 В.
- `uno_q_mcu/UNOQ_MOTOR.ino.elf-zsk.bin` - MCU-часть UNO Q: HMI/RPC, UART с Nucleo, ограничения запуска и тайм-ауты.
- `linux/web_hmi` - Linux-часть UNO Q: веб-интерфейс, журналирование и последовательность START/STOP.

## Перед записью

1. Полностью отключить J7/DC+ и DC-, дождаться разряда конденсаторов и проверить напряжение прибором.
2. Оставить двигатель и силовую сеть отключёнными. Питать только логическую часть плат от USB.
3. Соединить UART: UNO Q `D1/TX` -> Nucleo `PB7/USART1_RX`, UNO Q `D0/RX` <- Nucleo `PB6/USART1_TX`, а также общий `GND`.
4. Выход реле: Nucleo `PB4` -> резистор базы транзистора драйвера. Нужен аппаратный подтягивающий к земле резистор, чтобы реле было выключено во время reset. Для отладки Nucleo использовать SWD (`PA13/PA14`), не полный JTAG.

Проверка пакета и пробный запуск без записи:

```powershell
py -3 tools/verify_board_flash_package.py firmware/ready_to_flash
.\tools\flash_mic_ai_boards.ps1 -Target All -UnoPort COM5
```

Реальная запись трёх частей:

```powershell
.\tools\flash_mic_ai_boards.ps1 -Target All -UnoPort COM5 -Execute -ConfirmDcBusDisconnected
```

Можно прошивать отдельно через `-Target Nucleo`, `-Target UnoQ` или `-Target Linux`. Для нескольких ST-Link укажите `-StLinkSerial`, для нескольких ADB-устройств - `-AdbDevice`.

## Что проверено программно

- чистая сборка Nucleo: 0 ошибок, 0 предупреждений;
- сборка UNO Q для `arduino:zephyr:unoq`;
- совпадение UART-протокола v0x02 и числа пар полюсов;
- PB4 выключается при STOP, ESTOP, тайм-ауте UART и ошибке MCSDK;
- PWM разрешается только после Vbus не ниже 250 В и выдержки реле 350 мс;
- HMI ждёт фактический `PWM_ACTIVE` от Nucleo, а не только локальную команду START;
- контроль SHA-256 всех файлов пакета.

## Что нельзя подтвердить без стенда

В `reports/mcsdk_release_preflight.json` намеренно остаются открытыми аппаратная HIL-проверка предзаряда и измерение параметров конкретного экземпляра двигателя. До их закрытия прошивка является проверенным кандидатом для записи и низковольтного ввода в эксплуатацию, но не разрешением сразу подавать 310 В на DC-шину.

Первый аппаратный запуск выполняется без двигателя и без J7: проверить загрузку, UART, нулевой PB4 и телеметрию. Затем проверить PB4 и тайм-ауты на низком безопасном напряжении. Только после осциллографической проверки полярности, задержки и аварийного размыкания можно менять `MIC_PRECHARGE_HIL_VALIDATED` на `1` и проводить силовой запуск.
