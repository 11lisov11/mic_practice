# UNO Q - NUCLEO-G431RB: контракт UART для MCSDK ACIM V/F

Этот канал связывает UNO Q только с пользовательским адаптером официального проекта MCSDK. Он не является прямым управлением шестью PWM-входами IPM.

## Физическое соединение

Связь выполняется прямым UART 3,3 В внутри закрытого `HOT`-корпуса, `115200 8N1`:

| Направление | UNO Q | NUCLEO-G431RB |
|---|---|---|
| Команда в привод | `D1 / Serial1 TX` | `PB7 / USART1_RX` |
| Ответ и телеметрия | `D0 / Serial1 RX` | `PB6 / USART1_TX` |
| Общая точка отсчёта | `GND` | `GND` |

Шины `3V3` UNO Q и Nucleo между собой не соединяются. После объединения GND UNO Q, Nucleo и AS5600 относятся к `HOT`-домену; на STEVAL этот опорный GND электрически связан с `J7 DC-` и должен быть недоступен при включённой силовой части. В рабочем режиме наружу выходит только Wi-Fi; USB, ST-Link, Ethernet, HDMI, UART-адаптеры и измерительные провода отсутствуют. Флаг E-stop в кадре является программной командой остановки. Вход break/OCP силовой платы действует независимо от UART. Отдельная аппаратная цепь E-stop должна быть реализована и испытана до силового пуска.

## Разрешённый кадр

Размер кадра 32 байта, XOR CRC по байтам `0..30` находится в байте `31`.

| Байты | Значение |
|---|---|
| `0..1` | `AA 55` |
| `2` | Версия `0x02` |
| `3` | `0x01` только для запуска; `0x08` только для чистого `CLEAR`; `0x02` E-stop |
| `4` | Для запуска только `MODE_SCALAR = 3`; для остановки/CLEAR `MODE_OFF = 0` |
| `5` | Sequence |
| `6..9` | Частота статора в milliHz, little-endian |
| `10..13` | Историческое поле амплитуды; MCSDK его не использует, V/F задаётся профилем двигателя |
| `14..30` | Только нули |
| `31` | XOR CRC |

`MODE_DUTY`, `MODE_FOC`, `MODE_VECTOR`, `DIAG`, ненулевые сервисные поля, неверный CRC/версия, повтор последнего `ENABLE` с тем же `sequence`, частота вне текущего лимита профиля или тишина на линии более 300 мс вызывают `MC_StopMotor1()` и защёлкивают отказ. Снятие отказа возможно только чистым кадром `CLEAR` (`flags=0x08`, `mode=0`, все прочие поля нулевые). Повтор `CLEAR` разрешён, чтобы MCSDK мог завершить подтверждение внутреннего отказа.

Ответ возвращает тот же `sequence`, счётчики good/bad, статус link/fault/PWM и код отказа. Дополнительные поля ответа согласованы так:

| Байты | Значение ответа Nucleo |
|---|---|
| `14` | `0x00`; старый бит `0x08` зарезервирован и всегда сброшен |
| `17..18` | Vbus в десятых долях вольта, little-endian |
| `19..20` | температура радиатора в десятых долях градуса C, signed int16 little-endian |
| `21` | `0x01` температура действительна; `0x02` ошибка температуры |
| `29` | `0x80` формат MCSDK; `0x40` Vbus действителен; `0x20` внешняя шина устойчива после автономного soft-start |
| `31` | XOR CRC |

Nucleo не управляет внешним soft-start и не конфигурирует `PB4` как его выход. Он считает шину готовой после непрерывного нахождения `Vbus` в диапазоне `250...385 В` не менее `3,5 с`; при падении ниже `200 В` или превышении `385 В` готовность сбрасывается. Linux-HMI подтверждает запуск только после одновременного получения `softstart_ready` и фактического `PWM_ACTIVE`. Ручные команды `PRECHARGE/RELAY` запрещены, поскольку внешний модуль автономен.

## RPC и HTTP API

Позиционный результат UNO Q RPC `get` имеет схему версии 2 и содержит 78 элементов. Индексы `0..74` не переиспользуются:

| Индекс | Значение |
|---|---|
| `74` | `precharge_managed=0`; сохранённая безопасная семантика старого клиента |
| `75` | `rpc_schema_version=2` |
| `76` | `softstart_ready` |
| `77` | capability-mask контроллера: `0x01` V/f, `0x02` FOC, `0x04` MIC |

Сервер намеренно считает 75-элементный переходный массив неоднозначным: `softstart_ready=0`, список поддерживаемых режимов пуст, пуск блокируется. Это исключает ошибочное толкование индекса `74` старым и новым ПО.

В HTTP `/api/status` канонический префикс телеметрии контроллера - `mc_*`: `mc_fault`, `mc_bad_cnt`, `mc_vdc`, `mc_temp_c`, `mc_softstart_ready` и другие. Префикс `bp_*` временно публикуется как deprecated-алиас для чтения старых журналов и инструментов; HMI его больше не использует. Команда `BPFOC` также остаётся только переходным алиасом. Текущий Nucleo V/f backend отвергает включение FOC, а HMI отключает FOC/MIC по capability-mask.

## Сборка

Собрать обе прошивки и манифесты:

```powershell
powershell -ExecutionPolicy Bypass -File C:\mic_practice\tools\build_firmware_bundle.ps1
```

Перед сборкой команда автоматически проверяет версию, длину кадра, запрещённые режимы, поля сервиса, timeout и то, что адаптер Nucleo не трогает PWM напрямую. После сборки сверяются SHA-256, размеры и состав обоих комплектов. Это статическая проверка и тест векторов протокола; она не заменяет HIL-испытание.

Результаты:

- `mcsdk_reference/AIR56B2_025KW_220V_DELTA_NAMEPLATE_VF_NOT_FOR_HV/STM32CubeIDE/Debug` - Nucleo `ELF/BIN/HEX`, журнал сборки и манифест.
- `firmware/unoq_mcsdk_scalar` - UNO Q `BIN/ELF/HEX`, готовый upload-пayload `UNOQ_MOTOR.ino.elf-zsk.bin` и манифест. Для текущего dynamic link mode прошивается именно файл `*.elf-zsk.bin`; обычный `*.bin` оставлен для анализа.

Это кандидат V/f для АИР56В2 с числовым профилем по каталожным данным, подтверждённым оператором. Проверка профиля подтверждает согласованность чисел в JSON, IOC, исходниках UNO Q/Nucleo и манифестах, но не происхождение данных конкретного экземпляра двигателя. До приложения фотографии шильдика, измерений, полной схемы Nucleo/IHM09M2/IPM15B и аппаратных испытаний HV-gate намеренно запрещает силовой пуск.
