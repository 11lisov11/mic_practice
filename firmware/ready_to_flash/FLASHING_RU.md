# Комплект прошивок MIC_AI

Этот комплект предназначен для `NUCLEO-G431RB` (`STM32G431RBT6`), переходной платы `X-NUCLEO-IHM09M2`, силового модуля `STEVAL-IPM15B` и `Arduino UNO Q`. Это именно UNO Q: бинарник не подходит для классической Arduino Uno AVR.

## Что прошивается

- `nucleo/ACIM-NUCLEOG431RB-IPM15B-VF_OL.hex` - MCSDK 6.4.2, разомкнутое скалярное V/f для IEK AIR56B2: 1 пара полюсов, 50 Гц, 2720 об/мин, двигатель соединён треугольником на 220 В.
- `uno_q_mcu/UNOQ_MOTOR.ino.elf-zsk.bin` - MCU-часть UNO Q: HMI/RPC, UART с Nucleo, ограничения запуска и тайм-ауты.
- `linux/web_hmi` - Linux-часть UNO Q: веб-интерфейс, журналирование и последовательность START/STOP.

## Перед записью

1. Полностью отключить J7/DC+ и DC-, дождаться разряда конденсаторов и проверить напряжение прибором.
2. Оставить двигатель и силовую сеть отключёнными. Питать только логическую часть плат от USB.
3. Штатный UART собрать напрямую: UNO Q `D1/TX` -> Nucleo `PB7/USART1_RX`; Nucleo `PB6/USART1_TX` -> UNO Q `D0/RX`; UNO Q `GND` -> Nucleo `GND`. Линии `3V3` плат не соединять.
4. После объединения GND UNO Q становится частью HOT-контура. В силовом режиме обе платы находятся внутри закрытого корпуса, а наружу выходит только Wi-Fi.
5. `PB4` никуда не подключать. Автономный сетевой soft-start устанавливается перед выпрямителем и не имеет управляющего соединения с Nucleo или Uno Q. Для отладки Nucleo использовать SWD (`PA13/PA14`), не полный JTAG.
6. При питании DC-шины от сетевого моста Nucleo относится к HOT-стороне. Перед подачей сети отключить от него USB/ST-Link и любые неизолированные приборы, связанные с ПК. Прошивка выполняется только при отключённой и разряженной DC-шине.

Из корня репозитория проверка пакета и пробный запуск без записи:

```powershell
py -3 tools/verify_board_flash_package.py firmware/ready_to_flash
.\tools\flash_mic_ai_boards.ps1 -Target All -UnoPort COM5
```

Из корня распакованного `ready_to_flash.zip` используются локальные команды:

```powershell
py -3 .\tools\verify_board_flash_package.py .
.\tools\flash_mic_ai_boards.ps1 -Target All -UnoPort COM5
```

Реальная запись трёх частей:

```powershell
.\tools\flash_mic_ai_boards.ps1 -Target All -UnoPort COM5 -Execute -ConfirmDcBusDisconnected
```

Можно прошивать отдельно через `-Target Nucleo`, `-Target UnoQ` или `-Target Linux`. Для нескольких ST-Link укажите `-StLinkSerial`, для нескольких ADB-устройств - `-AdbDevice`.

## Что проверено программно

- чистая сборка Nucleo: 0 ошибок, 0 предупреждений;
- сборка UNO Q для `arduino:zephyr:unoq`;
- совпадение UART-протокола v0x02 и числа пар полюсов;
- старый UART-бит реле всегда равен нулю, а GPIO управления реле в Nucleo отсутствует;
- PWM разрешается только после непрерывно допустимого Vbus `250...385 В` в течение не менее 3,5 с;
- переход к новой частоте V/f выполняется рампой 3 секунды;
- HMI ждёт фактический `PWM_ACTIVE` от Nucleo, а не только локальную команду START;
- контроль SHA-256 всех файлов пакета.

## Что нельзя подтвердить без стенда

В `reports/mcsdk_release_preflight.json` намеренно остаются открытыми аппаратная HIL-проверка внешнего soft-start и измерение параметров конкретного экземпляра двигателя. До их закрытия прошивка является проверенным кандидатом для записи и низковольтного ввода в эксплуатацию, но не разрешением сразу подавать 310 В на DC-шину.

Первый аппаратный запуск выполняется без двигателя и без J7: проверить загрузку, UART, нулевой устаревший бит реле и телеметрию. Затем отдельно проверить ограничение пускового тока, время внутреннего шунтирования NTC, устойчивость DC-шины и повторное включение внешнего модуля. Только после этой проверки можно менять `MIC_EXTERNAL_SOFTSTART_HIL_VALIDATED` на `1` и переходить к силовому этапу S1 по `FIRMWARE_STAGES_RU.md`.
