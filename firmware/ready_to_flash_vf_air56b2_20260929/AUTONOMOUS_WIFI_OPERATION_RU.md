# Автономная работа MIC_AI по Wi-Fi

## Рабочая топология

`телефон/ноутбук <- Wi-Fi -> UNO Q (HOT) -> прямой UART -> NUCLEO-G431RB -> IHM09M2 -> STEVAL-IPM15B`.

UNO Q, Nucleo, AS5600, IHM09M2, шлейф FC-34P и STEVAL находятся внутри закрытого корпуса и считаются частью опасного `HOT`-домена. Общая `HOT_GND` через STEVAL электрически является `J7 DC-`. В силовом режиме к стенду не подключаются USB, ST-Link, Ethernet, HDMI, UART-адаптер, Saleae, осциллограф или другой провод от внешнего устройства.

Wi-Fi не является каналом функциональной безопасности. На стенде обязательны локальный двухполюсный выключатель и аппаратная аварийная остановка, снимающая разрешение силовой части независимо от Linux, браузера и UART.

## Два режима сети

### Через роутер

Один раз, только в сервисном режиме:

```powershell
python tools\configure_unoq_autonomous_wifi.py --mode station --ssid "LAB_WIFI" --password "LONG_WIFI_PASSWORD" --confirm-service-mode
```

После перезапуска UNO Q получает адрес по DHCP. HMI открывается по `http://<UNO_Q_IP>:8080`.

### Автономная точка доступа

Один раз, только в сервисном режиме:

```powershell
python tools\configure_unoq_autonomous_wifi.py --mode ap --ssid "MIC_AI_STAND" --password "LONG_AP_PASSWORD" --confirm-service-mode
```

Телефон подключается к `MIC_AI_STAND`, HMI открывается по `http://192.168.77.1:8080`. Пароль Wi-Fi и ключ управления HMI должны быть разными.

## Установка HMI

Первичная установка выполняется по ADB только при физически отключённых сети, выпрямителе и J7, а также после измерения разряда DC-link:

```powershell
python tools\adb_deploy_web_hmi.py --standalone-hv --restart --confirm-service-mode
```

При первой установке установщик создаёт ключ управления и сохраняет его только на UNO Q с правами `0600`. Повторное развёртывание сохраняет существующий ключ, поэтому уже настроенный телефон не теряет доступ. Значение не выводится в журнал установки.

До отключения ПК ключ однократно считывается в сервисном режиме и вводится в HMI на телефоне:

```powershell
adb shell cat /home/arduino/.config/mic-ai/control_token
```

Не сохранять ключ в репозитории, отчётах или снимках экрана. После проверки доступа закрыть сервисный режим и физически отключить ADB/USB. Сервис HMI запускается автоматически после загрузки Linux и перезапускается при сбое.

Перед первым силовым разрешением выполнить двухточечную проверку канала DC-шины по [AUTONOMOUS_VBUS_CALIBRATION_RU.md](AUTONOMOUS_VBUS_CALIBRATION_RU.md). Она проводится с телефона через Wi-Fi и не требует подключения ПК к стенду.

## Отказобезопасность

- Команды пуска, настройки, разрешения HV и скачивание логов требуют отдельный ключ HMI.
- `STOP/ESTOP` принимается без ключа, чтобы остановка не зависела от авторизации.
- Браузер отправляет heartbeat раз в секунду. Потеря heartbeat более чем на 3 секунды во время активного разрешения вызывает `STOP`, затем `ESTOP`.
- Nucleo независимо защёлкивает отказ при тайм-ауте UART более 300 мс.
- Разрешение HV ограничено TTL, а каждый пуск имеет конечный `RUNLIMIT`.
- После перезагрузки система начинает в остановленном состоянии; автоматического пуска нет.
- Разрешение HV закрыто до проверки Vbus в нулевой и известной рабочей точках. Запись хранится на eMMC UNO Q и автоматически отвергается после смены build ID UNO Q или Nucleo.

## Журналы

Журнал статуса, команд, отказов, потери heartbeat и защит хранится на eMMC UNO Q. Лимит штатного файла — 64 MiB. Выгрузка выбранного интервала выполняется кнопкой «Скачать» в HMI и требует ключ управления. Наличие ПК в момент испытания не требуется.

Для пассивной записи на ПК через Wi-Fi доступен `tools/collect_wifi_telemetry.py`. Он выполняет только HTTP GET `/api/status` и `/api/logs`; команд START, ARM, STOP или изменения прошивки в нём нет. Ключ задаётся через `UNOQ_CONTROL_TOKEN` либо `--token-file` с путём **вне репозитория**. Например, при уже настроенном локальном файле ключа:

```powershell
.venv\Scripts\python.exe tools\collect_wifi_telemetry.py `
  --url http://192.168.1.138:8080 `
  --token-file "$env:USERPROFILE\.config\mic-ai\control_token" `
  --seconds 60 --interval 0.5 --expect-idle --max-vdc 2 `
  --outdir artifacts\wifi_idle_check
```

Каталог вывода должен быть новым. `status.jsonl` содержит временные метки ПК и полные ответы HMI, `logs.txt` — журнал, `summary.json` — сводку по свежести UART, состоянию и счётчикам. При `--expect-idle` увеличение счётчиков ошибок или разрешение PWM делает проверку неуспешной. Для физически разряженной шины отдельно укажите `--max-vdc 2`, чтобы любое превышение в телеметрии тоже провалило проверку; `--expect-idle` сам по себе не означает нулевую шину. Доступность журнала требует того же ключа, что и управление; не помещать ключ в отчёт, командную строку или Git. Ненарастание ошибок за короткий интервал не отменяет ранее накопленные ошибки и не подтверждает готовность силовой части.

При физически снятом `STEVAL J7`, отключённом двигателе и измеренном напряжении DC-шины менее 2 В маршрут управления можно проверить без разрешения выхода:

```powershell
.venv\Scripts\python.exe tools\verify_wifi_command_path.py `
  --token-file "$env:USERPROFILE\.config\mic-ai\control_token" `
  --outdir artifacts\wifi_command_path_check `
  --confirm-j7-disconnected --confirm-motor-disconnected --confirm-dc-below-2v
```

Сценарий посылает по Wi-Fi `MODE VF` и уставки `SET FREQ 5`, `20`, `0`, сверяет ответную телеметрию и требует, чтобы `START` был отклонён при нулевой шине и активном коде отказа `5`. Этот код является обобщённым `UNO_FAULT_INTERNAL`, а не однозначным диагнозом пониженного напряжения. Затем сценарий посылает `STOP` и проверяет отключение выхода. Он не доказывает работу PWM, dead-time, разгон двигателя или защиту силового каскада; для них нужны отдельные испытания. Каталог вывода также должен быть новым. Если ключ ещё не настроен на ПК, его можно вводить через переменную окружения, не помещая в репозиторий или командную строку.

Обновление прошивки и изменение сетевого профиля допускаются только в сервисном режиме без силовой части. При подключённой шине эти операции запрещены, даже если выполняются по Wi-Fi.
