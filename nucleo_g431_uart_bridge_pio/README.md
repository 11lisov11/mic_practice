# NUCLEO-G431RB UART bridge

Это промежуточный проект для проверки связи `UNO Q <-> NUCLEO-G431RB` и низковольтной проверки выводов до генерации официального ACIM-проекта в MCSDK.

Что реализовано:

- `USART1`, `PB6/TX`, `PB7/RX`, `115200 8N1`;
- существующий 32-байтный протокол версии `0x02`;
- CRC, sequence, счётчики good/bad и timeout `300 мс`;
- немедленный stop при E-STOP, timeout или неподдерживаемой команде запуска;
- формат ответа, совместимый с текущей прошивкой UNO Q.

Профиль по умолчанию `nucleo_g431_uart_bridge` намеренно не реализует:

- TIM1 PWM, ADC, break input и управление STEVAL-IPM15B;
- V/F, FOC и MIC;
- реле, тормоз и вентилятор;
- реальная телеметрия шины, токов и температуры.

`motor_backend_stub.cpp` всегда отклоняет `ENABLE` с `FAULT_INTERNAL` и не конфигурирует ни одного силового вывода. Это не motor-control прошивка и не разрешение подавать J7.

Отдельный профиль `nucleo_g431_pwm_bench` реализует только диагностический низковольтный контур:

- TIM1 complementary PWM на шести выводах IHM09M2, `10 кГц`, dead-time `2 мкс`;
- запуск только командой `MODE_DIAG` с флагами `ENABLE | DIAG_PWM`;
- принудительный останов при timeout связи, ошибке кадра или любой другой команде;
- опрос пяти ADC-каналов для проверки разводки;
- `PA6/J7-1 EM_STOP` всё время удерживается в активном низком уровне.

У bench-профиля аппаратный `BREAK` отключён, нет силовой логики, V/F, FOC и MIC. Его разрешено прошивать и проверять логическим анализатором только при физически отключённом `J7` и обесточенной силовой шине. Подключать его к IPM или подавать высокое напряжение запрещено.

Сборка:

```powershell
py -3 -m platformio run -d C:\mic_practice\nucleo_g431_uart_bridge_pio
py -3 -m platformio run -d C:\mic_practice\nucleo_g431_uart_bridge_pio -e nucleo_g431_pwm_bench
py -3 -m platformio run -d C:\mic_practice\nucleo_g431_uart_bridge_pio -e nucleo_g431_uart_bridge_vcp
py -3 -m platformio run -d C:\mic_practice\nucleo_g431_uart_bridge_pio -e nucleo_g431_pwm_bench_vcp
```

На стенде без J7 допускается прямой UART для проверки. В итоговой сборке между UNO Q и Nucleo обязателен двухканальный изолятор; земли `SAFE_GND` и `HOT_GND` не соединяются. Полная коммутация описана в `C:\mic_practice\NUCLEO_G431_MIGRATION_RU.md`.

После генерации MCSDK-проекта этот каталог используется как источник модулей `proto`, `uart_link` и `bridge_controller`. Stub заменяется адаптером к публичному API MCSDK; системный clock, TIM1, ADC, fault/break и pin mapping берутся только из MCSDK/CubeMX.

## Профили UART и вычислительный тест

Профили без суффикса используют `USART1 PB6/TX + PB7/RX` для будущей изолированной связи с UNO Q. Профили с суффиксом `_vcp` используют штатную разводку Nucleo `PC4/TX + PC5/RX` до встроенного STLINK-V3E и доступны через его виртуальный COM-порт. Эти варианты нельзя смешивать: конкретная сборка обслуживает только одну пару выводов.

`nucleo_g431_pwm_bench` и `nucleo_g431_pwm_bench_vcp` запускают на частоте 20 кГц вычислительную нагрузку из PI-регулятора токов, предиктивного регулятора, наблюдателя возмущения и SVM. Расчётная скважность намеренно не записывается в TIM1: физические выходы сохраняют фиксированный диагностический шаблон 50 %, а `PA6/J7-1` удерживается в активном `EM_STOP`.

Перед преобразованием Clarke/Park применяется ограничитель одиночного выброса и НЧ-фильтр измеренного тока с тестовой полосой около 2,5 кГц. Невалидный вход, повреждённое численное состояние, `NaN/Inf` или превышение 25-мксекундного бюджета очищает вычисленный output и защёлкивает останов. Параметры тестовой модели `R/L` не являются параметрами двигателя и должны быть заменены результатом идентификации.

Каждое прерывание отмечается активным LOW-импульсом на `PC6`, доступном на `CN10 pin 4`. `PC13` не используется, поскольку он соединён с кнопкой `B1`. Логический анализатор подключается только при снятом J7 и обесточенной силовой части:

| Saleae | Nucleo | Сигнал |
|---|---|---|
| `CH0` | `PA8` | U high |
| `CH1` | `PA7` | U low |
| `CH2` | `PA9` | V high |
| `CH3` | `PB0` | V low |
| `CH4` | `PA10` | W high |
| `CH5` | `PB1` | W low |
| `CH6` | `PA6` | активный LOW `EM_STOP` |
| `CH7` | `PC6 / CN10-4` | активная LOW метка ISR |

После экспорта `digital.csv` проверка времени выполняется так:

```powershell
py -3 C:\mic_practice\tools\nucleo_control_timing_analyze.py C:\path\digital.csv --channel 7 --expected-hz 20000 --budget-us 25 --max-period-error-us 2 --min-pulses 100
```

Тест проходит только при отсутствии пропущенных ISR, максимальном времени вычисления не более 25 мкс и ошибке периода не более 2 мкс. Это пока проверка вычислительной производительности, а не готовый FOC для двигателя.
