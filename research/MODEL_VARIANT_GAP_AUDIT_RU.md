## 1. Итог аудита

В репозитории уже есть пригодная для исследований программная основа:

- потоковая модель асинхронного двигателя в неподвижных координатах alpha-beta;
- модель двухуровневого инвертора с допустимыми векторами, dead-time,
  минимальным импульсом и приближенными потерями;
- базовые FOC-SVM, FCS-MPC, DTC, DTC-SVM, deadbeat-current и исследовательский
  sensorless/adaptive FOC;
- прямые методы выбора вектора Protected H1, SNH-PWM и C6-RV-PWM;
- защитный шлюз с проверками тока, напряжения, температуры, dead-time,
  watchdog и атомарности последовательности;
- модельно-ориентированная идентификация с SVD/rank-gate, независимой
  валидацией и запретом выпуска deployment-профиля из синтетических данных;
- паспортно-ограниченный ансамбль AIR56B2, F1S/F2/F3, многорежимный V/f и
  encoder-observer FOC с раздельными train/validation/evidence-файлами;
- статистические валидаторы, парные Monte Carlo серии, conformal-анализ и
  машинные аудиты допустимых научных утверждений.

Главный пробел состоит не в количестве алгоритмов, а в отсутствии единого
физически независимого экспериментального контура. В большинстве host-сравнений
объект, предиктор и часть наблюдателя основаны на одной alpha-beta модели. Это
создаёт риск inverse crime: алгоритм может выигрывать на той же структуре, по
которой он прогнозирует. Кроме того, полные исходники обучения FOC+PPO в текущий
срез не перенесены, классический loss-model/flux-optimization baseline отсутствует
как исполняемый регулятор, а sensorless baseline ещё использует недоступные на
реальном стенде потоковые состояния.

Поэтому текущую модель AIR56B2 нельзя считать точной моделью конкретного
двигателя. На правильном этапе до получения плат следует строить и использовать
**nameplate-constrained ensemble**, то есть семейство физически допустимых моделей,
согласованных с паспортом, и проверять каждый алгоритм на всём семействе и на
отдельном holdout-семействе.

## 2. Граница знания об AIR56B2

### 2.1. Паспортные и прямо вычислимые величины

| Величина | Значение | Статус | Комментарий |
|---|---:|---|---|
| Номинальная механическая мощность `P_N` | `250 Вт` | паспорт | Не входная электрическая мощность. |
| Линейное напряжение `U_LL` | `220 В RMS` | паспорт | Только для соединения Delta. |
| Линейный ток `I_L` | `1,24 А RMS` | паспорт | Ток линии при Delta. |
| Коэффициент мощности `cos phi_N` | `0,78` | паспорт IEK | Используется для проверки активной входной мощности. |
| КПД `eta_N` | `0,68` | паспорт IEK | Используется для независимой проверки входной мощности и потерь. |
| Частота `f_N` | `50 Гц` | паспорт | Номинальная электрическая частота. |
| Скорость `n_N` | `2720 об/мин` | паспорт | Номинальная механическая скорость. |
| Число пар полюсов `p` | `1` | паспорт/следствие исполнения B2 | Даёт синхронную скорость 3000 об/мин при 50 Гц. |
| Схема обмоток | `Delta` | паспорт IEK: 220/380 В Delta/Y | Физическое напряжение каждой обмотки равно 220 В RMS. |
| Кратность пускового тока | `I_start/I_N = 5,3` | паспорт IEK | Ограничивает эквивалентную схему при `s=1`. |
| Кратность пускового момента | `M_start/M_N = 2,2` | паспорт IEK | Проверяется отдельной расширенной моделью пуска. |
| Кратность максимального момента | `M_max/M_N = 2,2` | паспорт IEK | Проверяется отдельной механической характеристикой. |
| Ток обмотки | `I_phase = I_L/sqrt(3) = 0,716 А RMS` | прямо вычисляется | Не заменять им линейный ток в поле MCSDK, если API ожидает линейный ток. |
| Эквивалентное phase-neutral напряжение MCSDK | `U_LL/sqrt(3) = 127,017 В RMS` | прямо вычисляется | Это координатный эквивалент для контроллера, а не физическое напряжение обмотки Delta. |
| Синхронная скорость | `n_sync = 60 f_N/p = 3000 об/мин` | прямо вычисляется | Для `p=1`. |
| Номинальное скольжение | `s_N = 9,33 %` | прямо вычисляется | `(3000-2720)/3000`. |
| Номинальная угловая скорость | `omega_N = 284,84 рад/с` | прямо вычисляется | Из 2720 об/мин. |
| Номинальный момент на валу | `M_N = P_N/omega_N = 0,878 Н·м` | прямо вычисляется | Средний момент при паспортной выходной мощности. |
| Полная входная мощность | `S_N = sqrt(3) U_LL I_L = 472,48 В·А` | прямо вычисляется | Не является активной мощностью и не определяет потери. |
| Активная мощность по `U/I/cos phi` | `P_1 = 368,55 Вт` | прямо вычисляется | Независимая паспортная проверка. |
| Активная мощность по `P_2/eta` | `P_1 = 367,65 Вт` | прямо вычисляется | Расхождение 0,246 % объясняется округлением паспорта. |
| Суммарные потери | `P_loss = 117,65 Вт` | прямо вычисляется | Их разбиение по видам не определяется однозначно. |

Официальный каталог позволяет вычислить активную входную мощность, КПД и общую
мощность потерь. Он не позволяет однозначно разделить потери и восстановить
`Rs/Rr/Lls/Llr/Lm/J/B`. Ранее записанные `cos_phi=0,68`, `eta=0,75` были
ошибочны и исправлены на паспортные `0,78` и `0,68`. Значение `J=0,01` никогда
не являлось паспортным и сохраняет только статус устаревшего simulation prior.

Значение `RS=0,35 Ом` в сгенерированном V/f-проекте также нельзя трактовать как
измеренное сопротивление AIR56B2. Для разомкнутого V/f оно является служебной
заготовкой и не разрешает выпуск LSO-FOC.

### 2.2. Невосстанавливаемые из паспорта параметры

| Параметр | Почему не определяется однозначно | Допустимое использование до измерений |
|---|---|---|
| `Rs` | Нужны DC/AC измерения обмотки и температура. Общие паспортные потери не разделяют медь статора и остальные потери. | Случайная положительная величина ансамбля; температурный закон задаётся отдельно. |
| `Rr` | Зависит от скольжения, схемы замещения и разделения потерь; одна номинальная точка недостаточна. | Случайная величина ансамбля с проверкой воспроизведения номинального скольжения. |
| `Lls`, `Llr` | Раздельные рассеяния структурно слабо различимы по доступным сигналам; текущий rank-аудит подтверждает потерю ранга. | Использовать наблюдаемое `Lsigma` и nuisance-коэффициент распределения между `Lls/Llr`. |
| `Lm` | Требуется опыт холостого хода или динамическая идентификация; по одному `U/I` нельзя отделить намагничивание от нагрузки и потерь. | Случайная величина ансамбля, возможно с нелинейной кривой насыщения. |
| `J` | Паспорт двигателя не задаёт инерцию ротора и присоединённой механики. | Широкое семейство `J_motor + J_load`; отдельно проверять чувствительность. |
| `B` | Механические, вентиляционные и нагрузочные потери не разделены. Часто закон не является чисто вязким. | Семейство моделей трения: вязкое, кулоновское и аэродинамическое. |

Ни оптимизация, ни нейросеть не могут превратить эти величины в идентифицированные
без дополнительных наблюдений. Подгонка к одной паспортной точке определяет
множество допустимых параметров, а не единственную физическую точку.

## 4. Рекомендуемое семейство AIR56B2 до аппаратной идентификации

### 4.1. Не одна модель, а иерархия fidelity

Минимально необходимы пять уровней объекта:

1. `F0 linear`: линейная alpha-beta модель, идеальный инвертор, постоянный момент.
   Нужна для отладки формул и быстрых тысяч прогонов.
2. `F1 uncertainty`: та же электрическая структура, но ансамбль
   `Rs/Rr/Lsigma/Lm/J/B/Tload` и nuisance-разделение `Lls/Llr`.
3. `F1S starting`: феноменологическая потеря при большом скольжении, которая
   согласует пусковой и максимальный моменты с паспортом, но не выдаётся за
   уникально идентифицированную схему ротора.
4. `F2 loss-thermal`: насыщение, temperature-dependent `Rs/Rr`, потери в стали,
   механические потери и динамика температуры.
5. `F3 sim-to-real`: неидеальный инвертор, ripple Vdc, dead-time distortion,
   ADC/AS5600 quantization, offset, gain drift, sampling delay, packet jitter и
   отказы датчиков.

Финальный алгоритм не должен обучаться и приниматься на одном уровне. Например,
PPO обучается на смеси `F1/F2`, настраивается по отдельным seed, а окончательно
оценивается на невидимом `F3` и на структурно независимом reference plant.

### 4.2. Параметризация ансамбля

Рекомендуемый вектор неопределённости:

```text
theta = {
  Rs_20, alpha_Rs, Rr_20, alpha_Rr,
  Lsigma, leakage_split_k, Lm0, psi_sat, sat_exp,
  J_motor, J_load, B_viscous, T_coulomb, k_fan,
  Tload_profile,
  inverter_Ron, inverter_Vdrop, dead_time, Vdc_ripple,
  current_gain, current_offset, voltage_gain, sample_delay,
  speed_quantization, speed_delay
}
```

Положительные электрические параметры следует выбирать в log-space. Вместо
ложной отдельной идентификации `Lls/Llr` используется `Lsigma` и коэффициент
`leakage_split_k`, который остаётся nuisance-параметром. Для каждого кандидата
проверяются положительность параметров, невырожденность индуктивной матрицы,
численная устойчивость и допустимость токов.

Паспорт используется как система ограничений, а не как формула восстановления:

- при `50 Гц`, `220 В Delta` и нагрузке около `0,878 Н·м` должна существовать
  устойчивая номинальная область;
- скорость должна быть согласована с `2720 об/мин`, а линейный ток с `1,24 А`
  в заранее объявленных допусках;
- выходная механическая мощность должна быть согласована с `250 Вт`;
- модели, которым для этого нужны отрицательные потери, неустойчивая матрица или
  недопустимые токи, отбрасываются;
- паспортные `cos phi=0,78` и `eta=0,68` используются как независимые constraints;
  их согласованность по входной мощности проверяется с учётом округления.

Такой отбор оставит широкое множество параметров. Это правильный результат:
неопределённость должна сохраняться до аппаратных измерений.

### 4.3. Разделение выборок

Для каждого зафиксированного протокола нужны три непересекающихся семейства:

- `train ensemble`: обучение PPO, residual twin и настройка регуляторов;
- `validation ensemble`: выбор гиперпараметров и acceptance thresholds;
- `blind holdout ensemble`: итоговое сравнение, которое не используется при
  настройке;
- `OOD stress family`: параметры и структурные варианты за границей принятого
  паспортно-ограниченного семейства. Это проверка отказоустойчивости, а не часть
  заявления о nominal performance.

Seed, диапазоны, ограничения, число отклонённых кандидатов и причина отклонения
должны сохраняться в evidence JSON.

## 5. Минимальная матрица базовых методов

До вывода о научном преимуществе FOC+PPO следует сравнить при одной полезной
работе нагрузки и одинаковом измерительном интерфейсе:

1. Scalar V/f.
2. FOC с постоянным `i_d_ref`.
3. FOC с расписанием потока по скорости/нагрузке.
4. FOC с классической loss-model optimization.
5. FOC с extremum seeking по измеряемой входной мощности.
6. FOC+PPO supervisory.
7. Дистиллированная LUT из PPO.
8. Oracle offline optimum по `i_d_ref`, используемый только как верхняя граница.

Для прямого PWM это отдельная статья и отдельная матрица:

1. FOC-SVM.
2. DTC hysteresis.
3. DTC-SVM.
4. Deadbeat current control.
5. One-step FCS-MPC.
6. Robust FCS-MPC/C6-RV-PWM.
7. Protected H1.
8. SNH-PWM.

Смешивать FOC+PPO supervisory и direct PWM в один главный вывод не следует. Первый
вопрос: даёт ли интеллектуальная коррекция потока дополнительный энергетический
выигрыш относительно сильной классической оптимизации. Второй вопрос: может ли
прямой выбор вектора улучшить динамику/коммутации при сохранении независимой
защиты.

## 7. Критерий общей готовности исследования

Компьютерную часть можно считать готовой к переносу на платы, когда одновременно
выполнены следующие условия:

- ни один файл или отчёт не называет nameplate prior идентифицированной моделью;
- обучение и итоговая приёмка используют разные модели и разные seed;
- FOC+PPO полностью воспроизводится из этого репозитория;
- PPO сравнен с сильным классическим loss-model baseline и oracle bound;
- sensorless контроллер не получает истинные скрытые состояния;
- energy claim использует одинаковую полезную работу нагрузки и многосекундные
  сценарии;
- минимум 30 парных повторов или заранее рассчитанная статистическая мощность;
- все защитные и regression tests проходят в чистом зафиксированном окружении;
- результат содержит не только среднее, но CI, worst case, failure count и
  чувствительность к model family;
- hardware measurement явно остаётся будущей внешней валидацией, пока реальный
  capture не принят аппаратным gate.
