## Подготовленный профиль и контрольные трассы

Сформирован [frozen_profile.json](frozen_profile.json) из существующего ансамбля AIR56B2 и конфигурации исследовательского наблюдателя. Все параметры схемы замещения имеют статус **simulation prior, не измерения нашего двигателя**. Наблюдатель исследовательский Python, не извлечённый из текущей прошивки G431; его коэффициенты зафиксированы без настройки по новым результатам на 5 Гц.

Использованы существующий независимый объект `CurrentFluxInductionMotorRk4` и `SensorlessFluxSlipObserver`. Нагрузочные режимы и профили:

| Профиль | Нагрузка после 0,55 с | Назначение |
|---|---:|---|
| 128 | 0 | Базовый контроль без внешней нагрузки |
| 128 | 35% паспортного момента | Диагностика нагруженного режима |
| 11 | 35% паспортного момента | Повтор одной ранее сохранённой диагностической точки |

Команда частоты статора плавно достигает 5 Гц за 0,35 с. Длительность каждого опыта 1,2 с, шаг 100 мкс, окно метрик — последние 0,5 с. Это частота питания, а не измеренная механическая частота ротора.

Инвертор в этом эталоне **усреднённый**, с существующей моделью проводящих потерь. Ключевой ШИМ, dead-time, динамические потери и полный энергетический баланс здесь не добавлены. Сохранены задержка и квантование токов из исходного исследования. Восстановление напряжения по duty использует точно известную номинальную шину, без моделирования погрешности её измерения. Поэтому это начальный эталон для сверки, а не полный реалистичный двойник стенда.

В каждом опыте параллельно работают два отдельных наблюдателя:

- диагностический получает точное приложенное напряжение из объекта;
- второй получает напряжение, восстановленное по номинальной шине и рассчитанным duty, без знания падения напряжения в объекте.

Истинная скорость используется только при вычислении метрик. Фазовые duty проверены на диапазон 0…1; обратное преобразование duty в αβ-напряжение численно совпадает с командой. Повтор исторической точки 11 дал среднюю абсолютную ошибку скорости **1,7406262724542623 рад/с**, побитно совпавшую с сохранённым значением на данном запуске. Это проверяет воспроизведение исходного Python-опыта.

Результаты: [reference_results.json](reference_results.json), три CSV-файла и [график](python_reference_5Hz.png). На графике и в JSON явно указано, что расчёт выполнен Python. Положительный valid в этих трассах не является доказательством точной оценки скорости. Нагруженный открытый V/f-режим не гарантирует поддержание скорости; эти опыты не называются успешным замкнутым sensorless-регулированием.

Воспроизведение из `C:/mic_practice`:

```powershell
python research/simintech/prepare_5hz_reference.py
```

## Продолжение после получения дистрибутива

1. Установить официальный SimInTech в бесплатном режиме и записать версию и доступность библиотек.
2. Собрать нативную схему: усреднённый инвертор → модель ACIM → механика; токи и восстановленное напряжение → исследовательский наблюдатель; истинная скорость → регистратор сравнения.
3. Проверить эквивалентную звезду, peak/RMS, одну пару полюсов и источник параметров. Не заменять исследовательские коэффициенты профилем рабочего MCU без отдельного согласования моделей.
4. Инициализировать и выполнить расчёт в демоверсии. Зафиксировать реальный счётчик блоков, число уравнений, журнал ограничений, нативный файл и хеши.
5. Выполнить 5 Гц с теми же начальными условиями; сравнить экспорт SimInTech с контрольными CSV, затем добавить переключения и погрешности измерений.

Действующая прошивка, параметры защит и стенд не изменялись. Команды START/ARM/CLEAR не передавались. Браузерная попытка завершена, сеанс `cua_repl` сброшен; оконный захват Windows и `node_repl` для GUI не использовались.
